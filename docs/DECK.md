# DECK — 덱을 설계하는 화면 (v8)

v6까지의 보상은 "셋 중 하나 고르기"였다. 카드는 작은 명령 버튼이었고, 덱을 만들어가는 선택이
얕았다. **간단하게 누르는 게임이 아니라, 복잡한 조합을 쉽게 비교하는 게임**으로 고치는 작업이다.

- v7(§1–§7): 카드를 덱의 부품으로 보이게 하고, 보상을 덱 설계 판단으로 바꿨다.
- v8(§8–§9): 투수가 존을 점진적으로 넓히고, 존 정보 자체가 보상이 됐다.

이 문서가 덱·보상·강화·유물·읽기 등급의 현행 계약이다.
`docs/DUEL.md` 맨 위 v8.2 절은 판정·타석·상태 전이의 현행 계약이다. 두 문서가 겹칠 때는
전투 규칙은 DUEL, 덱·보상·강화·유물·읽기 등급은 이 문서를 따른다.

---

## 1. 왜 이 축들인가 — 엔진에서 끌어낸 설계

시너지를 새로 지어내지 않았다. 아래는 전부 v6 엔진에 이미 있던 수식이며, v7은 그것을 **화면에 드러낼 뿐**이다.

| 엔진 사실 | 위치 | 덱 설계에 주는 의미 |
|---|---|---|
| 커버 안에 공이 들어오면 `hit:1` | `swingOdds` | 덱빌딩은 **적중률 설계가 아니다**. 적중은 계약이다 |
| `widthPenalty = (커버 장수 − 1) × 7` | `matchup` | **넓은 범위는 장타를 깎는다.** 이것이 중심 트레이드오프 |
| `familiarity = 숙련존이면 +12` | `matchup` | 시작 덱의 4숙련존이 범위 선택의 기준점 |
| `scout`는 공의 **행**(높음/중간/낮음)을 알려준다 | `pitchClue` | 행 정보는 **가로 3존 카드로만** 현금화된다 |
| `rally`·`finisher`는 `shape:'row'` | `CARDS` | 그래서 관찰 → 가로 범위가 실제 연계다 |
| `strike`는 `shape:'column'` | `CARDS` | v6에는 **열을 알려주는 수단이 없다**. 세로 카드는 정보를 못 받는다 |
| `lure`의 `expanded`는 커버를 상하좌우 1칸 확장 | `coverage` | 1존 → 십자 5존. 대신 widthPenalty가 늘어 파워가 깎인다 |
| 기다림 성장은 `shape!=='all'`이면 커버를 **1존으로 강제** | `coverage` | **넓은 범위 카드를 죽인다.** 성장과 덱은 충돌할 수 있다 |
| `bunt`는 `sacrifice:.70`, `hit:0` | `swingOdds` | 안타가 나오지 않는 카드. 3아웃 제한에서 아웃을 지불한다 |

마지막 두 줄이 v6 연결 경로가 270런에서 5승에 그친 이유다. `relay` 성장의 시그니처가 `bunt`로
고정돼 있었고, 아웃을 계속 지불하는 경로에 자동 정책이 갇혔다. v7은 시그니처 고정을 제거한다(§5).

## 2. 카드 분류 — 카드는 덱의 부품이다

모든 카드에 구조화된 메타데이터를 붙인다. 화면은 이 값을 읽어 렌더링하며, **설명 문구를 따로 쓰지 않는다.**

```js
role   : '관찰' | '범위' | '장타' | '진루' | '생존' | '집중'
axis   : 'point' | 'row' | 'column' | 'cross' | 'all' | null   // 커버 축
gives  : ['행 정보', '범위 +1', ...]    // 이 카드가 만드는 것
needs  : ['주자', ...]                  // 이 카드가 요구하는 것
```

`gives`/`needs`는 문자열 토큰이며, 연계 판정은 **토큰 일치**로 계산한다(§3). 카드를 추가할 때
연계 표를 손으로 갱신하지 않아도 되게 하기 위함이다.

---

## 3. 연계와 상충 — 손패에서 동시에 읽힌다

한 장을 고르면 손패의 나머지 카드에 **왜 맞물리는지**가 즉시 표시된다. 눌러서 설명을 외우는 방식이 아니다.

### 연계 (`deck.js: synergies`)

| 조합 | 근거 |
|---|---|
| `scout` → `rally`·`finisher` | 확인한 높이의 가로 3존이면 커버가 곧 적중 |
| `scout+` → `strike` | 강화 관찰은 열까지 준다. 세로 3존이 정보를 받는 유일한 경로 |
| `lure` → `slug`·BASIC | 1존이 십자 5존이 된다. 좁은 장타 베팅의 적중 폭을 넓힌다 |
| `setup` → `slug`·`finisher` | 집중은 타격 +8 / 파워 +5. 장타 계열에서 값이 가장 크다 |
| `flow` → `rally` | 기존 주자 최소 2베이스 + 사인 1베이스 |

### 상충 (같은 비중으로 표시한다)

| 조합 | 근거 |
|---|---|
| `lure` + 넓은 카드(`rally`·`strike`·`defend`) | 커버가 늘어 `widthPenalty`가 커지고 장타가 사라진다 |
| 기다림 성장 사용 + 넓은 카드 | 커버가 1존으로 강제돼 카드의 범위가 통째로 무효 |
| `bunt` + 3아웃 압박 | 안타가 없는 카드. 아웃을 지불한다 |

상충을 숨기지 않는 것이 이 화면의 핵심이다. 좋은 조합만 보여주면 다시 "정답 누르기"가 된다.

## 4. 보상 — 후보가 아니라 내 덱을 본다

보상 화면은 세 후보를 나열하지 않는다. **현재 덱의 구성**을 먼저 보여주고, 후보를 고르면
그 구성이 어떻게 변하는지 표시한다.

표시하는 덱 지표(`deck.js: deckProfile`):

- **범위 구성** — 축별 장수 (1존 / 가로 / 세로 / 십자 / 9존)
- **준비 : 스윙 비율** — 준비 카드가 너무 많으면 실제로 칠 카드가 없다
- **역할 분포** — 관찰 / 범위 / 장타 / 진루 / 생존 / 집중
- **중복 장수** — 같은 카드 N장
- **미사용 정보** — `gives`는 있는데 그것을 받는 `axis` 카드가 없는 경우

마지막 항목이 진단 문장이 된다(`deck.js: diagnose`):

> "관찰 3장이 행 정보를 주는데, 그 정보를 쓰는 가로 범위 카드가 1장뿐입니다."
> "넓은 범위 8장. 장타 수단이 없어 단타로만 득점해야 합니다."

후보를 선택하면 **변화량**을 함께 보여준다 — 어느 지표가 몇 장 늘고 주는지.

## 5. 보상 행동 — 추가만이 아니다

각 보상 단계에서 **행동 하나**를 고른다. 아무 때나 무료로 덱을 편집하는 방식이 아니다.
카드를 더 받을지, 약한 카드를 덜어낼지, 핵심 카드를 강화할지가 매번 충돌해야 한다.

| 행동 | 내용 | 제약 |
|---|---|---|
| **추가** | 후보 3장 중 1장을 덱에 넣는다 | 덱 최대 18장 |
| **제거** | 덱에서 1장을 뺀다 | 덱 최소 9장 |
| **강화** | 덱의 1장을 `+`판으로 바꾼다 | 이미 강화된 카드는 불가 |
| **유물** | 이번 단계에 제시된 2개 중 1개를 얻는다 | 이미 가진 유물은 불가 (§9) |
| **건너뛰기** | 덱을 그대로 둔다 | 성장은 그대로 획득 |

성장 단계는 행동과 무관하게 매 보상에서 1단계 오른다(v6과 동일).

### 강화(`+`) 효과

`plus` 플래그는 덱 항목(`{id, kind, plus}`)에 붙는다. 카드 종류를 늘리지 않고 기존 수식만 강화한다.

| 카드 | `+` 효과 | 엔진 지점 |
|---|---|---|
| 공격 카드 전체 | `power +1` (파워 +18) | `matchup` |
| `scout` 릴리스 간파 | 행 정보 → **행 + 열** 정보 | `pitchClue` |
| `setup` 타이밍 맞추기 | 집중 +1 → **+2** | `playCard` |
| `watch` 작전 확인 | 2장 → **3장** | `playCard` |
| `calm` 호흡 고르기 | 1장 → **2장** | `playCard` |
| `lure` 코스 조정 | 스윙 후 소멸 → **타석 끝까지 유지** | `resolve` |
| `flow` 히트앤드런 | 추가 1베이스 → **2베이스** | `battingResult` |

**적중 계약은 강화로도 깨지지 않는다.** `+`는 범위·파워·정보·진루만 바꾸며, 커버 안의 공을
아웃으로 되돌리는 강화는 없다.

## 6. 성장은 덱을 대신하지 않는다

v6의 `rewardChoices`는 성장의 `signature` 카드를 후보에 **항상** 끼워넣었다. 그래서
"기다림 트리 → 릴리스 간파 받기"로 정답이 굳었다.

v7은 `signature`를 제거하고 **친화 축**(`affinity`)으로 바꾼다. 성장은 특정 카드를 주지 않고,
그 성장이 값을 더해주는 **축**을 표시한다.

| 성장 | 친화 축 | 후보 풀 (정보 / 페이오프 / 보완) |
|---|---|---|
| 기다림 | `point` (1존 승부) | `scout` 관찰 / `slug` 장타 / `lure` 범위 |
| 연결 | `row` (가로 진루) | `rally` 진루 / `finisher` 장타 / `flow` 사인 |
| 행운 | `cross` (넓게 버티기) | `defend` 커트 / `calm` 생존 / `strike` 세로 |

후보는 `REWARDS[stage] ∪ AFFINITY_CARDS[growth]`이며 고정 한 장이 아니다. 같은 기다림 성장이라도
관찰을 늘릴지, 범위를 보완할지, 장타를 강화할지에 따라 다른 덱이 된다.

**기다림 풀에 `scout`이 먼저 오는 것은 취향이 아니라 기계적 요구다.** 이 성장은 *지켜본* 스트라이크로
충전되므로, 언제 지켜볼지 알려주는 정보 카드가 없으면 1존에 눈감고 거는 덱이 된다.
관찰을 빼고 측정했을 때 기다림 완주는 48/90 → 15/90으로 무너졌다.

`relay`의 풀에 `bunt`가 없는 것이 v6과의 핵심 차이다. v6은 번트를 시그니처로 강제했고,
그 경로는 270런에서 5승에 그쳤다.

## 7. 저장 스키마 v8

v6 `readDuel`은 덱을 `12~15장`, id를 `c0…cN` 연속, `nextId === deck.length`로 검증했다.
제거·강화가 들어가면 셋 다 깨진다.

- 저장 키: `9zone-read-v8` (이전 키 `9zone-deck-v7` · `9zone-growth-v6` · `9zone-zones-v5`는 **삭제하지 않는다**)
- `state.version = 8`
- `deck: [{id, kind, plus?}]` — 9~18장, id는 **유일하기만** 하면 되고 연속일 필요 없다
- `nextId`는 단조 증가하며 덱 길이와 무관
- `rewards: [{type, kind?, id?}]` — 행동 기록. 길이 === `stage`
- `relics: [key]` — 중복 없음. 길이와 내용이 `rewards`의 `relic` 기록과 정확히 일치해야 한다

자동 이관은 하지 않는다. 이전 저장은 각자의 키에 남고, v8은 새 런으로 시작한다.

## 8. 투수 레퍼토리 — 처음에는 읽히고, 나중에는 읽히지 않는다

투수는 9존을 처음부터 다 쓰지 않는다. 좁게 시작해서 넓어진다. 이것이 초반을 읽히게 만들고,
읽히지 않게 되는 후반을 위해 덱을 설계할 이유를 만든다.

- `ZONE_ORDER[style]`이 그 투수가 존을 꺼내는 순서다. 앞에서부터 N개가 이번 레퍼토리다.
- N = `zoneOpen + floor((타석 − 1) / WIDEN_EVERY)`, `zoneMax`에서 멈춘다.
- 2스트라이크에서는 `PUTAWAY_REACH`만큼 **일시적으로** 더 넓게 손을 뻗는다. 카운트가 풀리면 돌아온다.
- 레퍼토리 밖 존의 확률은 **정확히 0**이다. 낮은 게 아니라 던지지 않는다.

| 투수 | 시작 | 최대 |
|---|---:|---:|
| 루키의 승부 | 4존 | 6존 |
| 낮게 가라앉는 공 | 5존 | 7존 |
| 담장 앞의 수비 | 5존 | 8존 |
| 마지막 세 개의 아웃 | 7존 | 9존 |

`startBattle`은 시작 조준이 레퍼토리 안에 들어오도록 맞춘다. 그러지 않으면 타자가 그 투수가
한 번도 던지지 않는 존을 겨눈 채 경기를 시작한다.

관찰과 결합하면 강력하다. 루키는 낮은 존을 하나만 쓰므로, 릴리스 간파로 "낮은 공"을 확인하면
그 존이 100%로 확정된다. 이것은 버그가 아니라 초반에 관찰의 가치를 가르치는 장치다.
후반 투수는 같은 행에 존이 여럿이라 관찰이 3분의 1로만 좁혀준다.

## 9. 읽기 등급 — 정보는 보상이다

존 확률은 처음부터 숫자로 보이지 않는다. **명암·범주 낱말 → 구간 → 정확한 값** 순으로 올라간다.

| 등급 | 보이는 것 | 조건 |
|---|---|---|
| 0 범주 | 존의 밝기와 낱말 3단계(자주 / 가끔 / 드묾). 숫자 없음 | 관찰 점수 0~1 |
| 1 대략 구간 | `15~20%` 같은 5% 구간 | 관찰 점수 2~3 |
| 2 정확한 확률 | `17%` | 관찰 점수 4 이상 |

관찰 점수는 덱의 `role==='관찰'` 카드 수이며 강화한 관찰은 2점이다. 세 시작 덱 모두 1점이라
**모든 런은 3단계 범주만 보이는 상태로 시작한다.** 정확한 확률을 보려면 덱을 그쪽으로 짜야 한다.

**낮은 등급은 숫자를 감출 뿐, 틀린 숫자를 보여주지 않는다.** 등급 0의 명암과 낱말은 실제 확률을
자주 / 가끔 / 드묾으로 묶으며, 확률 0도 드묾과 같은 명암으로 보인다. 한 번도 안 던지는 존을
드문 존과 묶어 덜 말할 뿐 잘못된 숫자를 만들지는 않는다. 등급 1·2는 레퍼토리 밖 존을 `0%`로
정확히 표시한다. 구속 판독기가 있으면 등급 0에서도 그 존을 `안 씀`으로 확정 표시한다.

### 유물

덱과 별개의 획득물이며 보상에서 카드 행동과 **경쟁한다**. 단계마다 2종이 제시된다.

| 유물 | 효과 |
|---|---|
| 낡은 망원경 | 읽기 등급 +1 (상한 2) |
| 투구 기록장 | 등급과 무관하게 존 밖 볼 확률만 항상 정확히 |
| 구속 판독기 | 지금 쓰지 않는 존을 확정 표시 |

유물은 덱을 바꾸지 않는다. 기본 등급은 어디까지나 덱이 정하고 유물은 그 위에 얹힌다.

## 10. 아직 검증되지 않은 것

- 위 지표와 진단이 **사람의 덱 설계 판단을 실제로 돕는지**는 미검증이다. 자동 정책은 진단 문장을 읽지 않는다.
- 강화 7종의 상대 가치는 균형 검증을 거치지 않았다. `scout+`(열 정보)가 가장 강할 가능성이 높다.
- 덱 최소 9장 / 최대 18장은 설계값이며 플레이 검증 결과가 아니다.

  자동 완주가 155/270 → 188/270으로 올랐는데, 이것이 "초반은 읽히고 후반은 안 읽힌다"는 의도된
  곡선인지 그냥 쉬워진 것인지는 사람 플레이로 확인해야 한다.
