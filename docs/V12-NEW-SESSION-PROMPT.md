# 새 세션에 붙여 넣는 프롬프트

아래 블록을 그대로 복사해 새 세션 첫 메시지로 넣는다.
브랜치·이슈 번호는 상황에 맞게만 바꾼다.

```
9ZONE V12 UI/UX 루프 엔지니어링을 이어서 진행해. 저장소 jjsjb88-alt/9-baseball,
브랜치 claude/feedback-review-plan-vw24at, 추적 이슈 #84, 관련 PR #83.

시작 전에 이 순서로 읽어. 지정한 범위만 읽고 전체를 읽지 마.
1. docs/V12-PROGRESS.md 전체 — 지금 어디까지 왔는지. 한 바퀴 = 체크박스 한 줄.
2. docs/V12-LOOP-ENGINEERING.md 전체 — 한 바퀴 도는 법과 절대 계약 C1~C7.
3. docs/V12-REVIEW.md 의 "주요 발견과 반영" 표 — 원안이 틀렸던 지점.
4. docs/V12-MASTERPIECE.md §2 와 이번 단계에 해당하는 절.
5. docs/V12-DECISIONS.md 전체 — 미결정 항목에 막히는지 확인.
6. AGENTS.md §1 9축, §5 완료 정의.
HANDOFF.md는 맨 위 절 하나만.

이번 바퀴에 할 일은 docs/V12-PROGRESS.md의 "다음 한 바퀴"에 적힌 슬라이스 하나야.
단계 전체를 한 번에 끝내려 하지 마.

반드시 지킬 것:
- 커버는 coverageAt() 반환값으로만 그린다. shape로 추정하지 마.
- 연결은 스택 순서상 앞뒤 aimZone의 동일/8방향 인접이다. 카드가 닿는 게 아니다. 순번을 지우지 마.
- damageRate는 배율이다. 예상 HP 피해로 그리지 마.
- 읽기 등급은 0/1/2다. 2/4는 관찰 점수 임계값이야.
- 공개된 정보로만 시각·ARIA·소리를 만든다.
- 엔진 공식을 UI에서 다시 구현하지 말고 기존 함수를 호출해 읽어.
- !important는 레이어 우선순위가 반대다. 일괄 @layer 래핑 하지 마.
- 게임 규칙·확률·피해·카드 수치·런 구조는 건드리지 마. 표현 계층만이야.
- main push와 배포 금지. 작업 브랜치에만 push해.
- 테스트를 건너뛰거나 임계값을 완화해서 통과시키지 마.
- 검증 안 한 걸 검증했다고 쓰지 마.

한 바퀴 순서:
읽기 → 슬라이스 하나 고르기 → 결정 게이트 확인 → 실패하는 검사부터 쓰기 → 구현
→ 검사 통과하면 먼저 커밋 → 브라우저로 실제 확인하고 캡처를 직접 읽기 → 수정 있으면 후속 커밋
→ V12-PROGRESS.md와 docs/STATUS.md 갱신 커밋 → push → 다음 바퀴 한 줄 남기기

매 바퀴 검증:
pnpm install --frozen-lockfile && pnpm test && pnpm build
node scripts/zone-report.js 30        (수치가 바뀌면 표현만 바꾼 게 아니다. 되돌려)
node docs/design/v12/audit-static-and-engine.mjs
pnpm dev 로 390x844 / 844x390 / 1440x900 캡처해서 이미지를 직접 읽어

D1~D8이 아직 비어 있어. 미결정 항목에 의존하는 슬라이스는 시작하지 마.
막히면 임의로 정하지 말고 V12-PROGRESS.md의 "막힌 곳"에 한 줄 적고,
무엇이 왜 막혔고 선택지가 뭔지 한 번만 보고하고 그 바퀴를 끝내.
결정 없이 할 수 있는 일이 남아 있으면 그걸 먼저 해. P0 전체가 거기 해당해.

끝났다고 선언하려면 P0~P8이 전부 닫히고, 사람 검증 3문답을 통과하고,
HANDOFF.md가 최신이고, 사용자가 배포를 승인해야 해.
테스트와 빌드 통과는 완료의 증거가 아니야.

지금 P0-1부터 시작해.
```

## 자율 루프로 돌릴 때

`/loop` 를 쓰면 위 블록을 그대로 넣는다. 간격은 두지 않고 모델이 자체 조절하게 둔다.
한 바퀴가 끝나면 `V12-PROGRESS.md`가 갱신돼 있으므로 다음 바퀴가 이어서 집어 간다.

**결정 게이트에서 멈추는 것이 정상 동작이다.** 멈췄다고 프롬프트를 바꿔 우회시키지 않는다.
