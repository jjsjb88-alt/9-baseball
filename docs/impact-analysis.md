# 기능 변경 영향도 분석

기능 추가/수정 시 아래 순서를 고정한다.

1. 변경하려는 기능의 직접 영향 범위를 적는다.
2. UI/입력/게임 로직/저장/뷰포트/스크롤/플로우/테스트/배포의 9축을 모두 확인한다.
3. 전역 CSS·전역 이벤트·공용 엔진·저장 스키마는 고위험으로 표시한다.
4. 사이드이펙트 가능성이 있는 기존 화면을 구현 전에 선정한다.
5. 구현 후 해당 화면을 회귀 테스트하고, 재현된 버그는 테스트로 고정한다.
6. PR의 필수 체크 10개를 모두 완료한다.
7. 전체 테스트·smoke·production build를 통과한 뒤 merge한다.

코드 변경 PR에서는 `.github/workflows/impact-analysis.yml`이 PR 본문의 영향도 분석 계약을 자동 검사한다.
