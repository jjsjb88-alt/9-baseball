## 0. 가장 중요한 최신 사용자 판정

기존 A/B/C 시안은 사용자가 **셋 다 별로**라고 판정했다.

이후 D/E/F를 만들었다.
- D = Field First
- E = Batter Eye
- F = Tactical Sheet

사용자는 **“E F 같은 느낌이 괜찮은듯”**이라고 했고, E의 몰입감 + F의 정보 정리감을 결합하는 방향을 추천했다.

그러나 바로 이어서 최종 판정은:

> **“마스터피스가아닌데?”**

따라서 **E/F는 승인안이 아니다.**
E의 몰입형 시선 흐름과 F의 정보 구조는 참고 원리일 뿐이며, D1은 계속 미확정이다.

“추천으로 가자”를 D1 최종 승인으로 해석하지 않는다.
사용자가 Golden Master 화면을 실제로 보고 명시적으로 승인하기 전까지 P1-1을 열지 않는다.

## 4. 반드시 기억할 아트 품질 교정

과거 D/E/F 시안에 `assets/sprites-v3/pitcher-sinker-release.svg` 같은 저품질 투수 자산이 들어갔다.

사용자 피드백:
> “저 svg투수 덩어리는 왜자꾸 나오는거야”

> “고퀄이면 상관없는데 저건 무슨기준을 갖다놔도 엉망이잖아”

핵심은 **SVG가 문제가 아니라 자산의 완성도**다.

SVG / PNG / 도트시트 어느 포맷이든 아래를 통과해야 한다.
- 실루엣
- 인체 비례
- 키포즈
- 체중 이동
- 최소 3단 명암
- 손/발 방향
- 장비·배트·글러브 가독성
- 축소 시 판독성
- 주변 경기장/VFX와의 밀도 일치
- 같은 게임 세계에 속하는 느낌

결정용 시안에서도 기준 미달 배우를 placeholder로 넣지 않는다.
합격 자산이 없으면 배우를 비우거나 비인물 공간 표현으로 해결한다.

## 5. 현재 E/F가 마스터피스가 아닌 이유

### 경기장이 배경판 수준
현재는 공간감·조명·관중·마운드·홈플레이트·전경/중경/후경이 하나의 장면으로 연결되지 않는다.

### 타자가 장면에서 떠 있음
바닥 접지, 그림자, 림라이트, 공간광, 카메라 깊이와 통합되지 않아 스티커처럼 보인다.

### 9ZONE이 일반 3×3 UI
게임 이름 자체가 9ZONE인데 현재 보드는 일반적인 투명 3×3 그리드에 가깝다.
9ZONE은 로고급 전투 오브젝트이자 화면의 기억점이어야 한다.

### 카드가 일반 모바일 카드 UI
베이지 사각형 + 미니 3×3 + 텍스트 수준에서 벗어나지 못했다.
9ZONE만의 card shape language가 없다.

### 구조는 나아졌지만 “와”가 없음
E는 몰입형, F는 정리형이지만 둘 다 wireframe/목업 느낌을 벗어나지 못했다.

### 투수를 빼니 대결 구도가 약해짐
저품질 투수 제거는 맞지만 타자↔투수, 타자↔공, 타자↔9ZONE의 긴장감이 약해졌다.

### 모든 레이어가 따로 놈
경기장·타자·공 궤적·9ZONE·카드·HUD가 하나의 작품이 아니라 개별 레이어처럼 보인다.

## 6. Golden Master 설계 순서

박스 배치부터 하지 않는다.

### 1) 카메라 구도
먼저 key art 한 장처럼 설계한다.
- 플레이어의 시점
- 타자 크기
- 투수와의 대치
- 9ZONE의 공간 위치
- 공의 출발/도착

### 2) 경기장 공간
최소:
- 전경
- 타석
- 홈플레이트
- 내야
- 마운드
- 투수 거리감
- 외야/관중
- 조명

이 공간 계층이 읽혀야 한다.

### 3) 타자/투수 대치
좋은 배우 자산만 사용한다.
실루엣·무게중심·시선·손·배트·릴리스·하체가 모바일에서도 읽혀야 한다.

### 4) 9ZONE 시그니처화
일반 UI 그리드가 아니라 9ZONE 세계관의 핵심 전투 장치로 만든다.
홈플레이트/타석/투구 궤적/선택 반응이 한 시스템처럼 보여야 한다.

### 5) 카드 Shape Language
이름·타입·coverage·선택 상태·순서·메인/지원·조작 영역은 유지하면서
9ZONE 고유 silhouette / edge treatment / 재질 언어를 만든다.

### 6) 조명/VFX 통합
VFX로 저품질 아트를 숨기지 않는다.
좋은 아트를 rim light, ground shadow, stadium light, ball streak, atmosphere와 통합한다.

### 7) 정보 위계
F의 정리감을 참고하되 “하단에 판 하나 놓기”로 끝내지 않는다.
읽는 순서:
1. 상대/현재 상황
2. 판단 대상
3. 9ZONE
4. 카드/순서
5. 효율
6. 실행

## 7. 제품 의미 절대 계약

- C1: 커버는 `coverageAt()` 반환값으로만 표현.
- C2: CONNECT는 stack 순서의 앞/뒤 `aimZone`이 동일/8방향 인접일 때만.
- C3: `damageRate`는 HP 피해량이 아니라 배율.
- C4: read level은 0/1/2. 2/4는 관찰 점수 threshold.
- C5: 공개 정보만 시각/ARIA/사운드로 표현.
- C6: 엔진 공식을 UI에서 다시 구현하지 않음.
- C7: 기존 `!important`를 일괄 `@layer`로 감싸지 않음.

Golden Master가 정적이어도 이 의미를 거짓으로 표현하지 않는다.

## 11. Golden Master 자체 PASS 기준

사용자에게 보여주기 전 스스로 확인한다.

- 스크린샷만 봐도 야구 전투 화면임이 즉시 읽힘
- 타자가 스티커처럼 떠 있지 않음
- 상대 투수의 존재/투구 방향이 읽힘
- 9ZONE이 화면의 시그니처임
- 카드가 일반 웹 UI처럼 보이지 않음
- HUD가 경기 장면과 분리되지 않음
- 전경/중경/후경이 있음
- 광원 방향이 일관됨
- 배우/경기장/UI 아트 밀도가 맞음
- 작은 모바일에서도 핵심 판단이 읽힘
- “예쁘다”보다 “이 게임만의 화면”이 먼저 느껴짐
- 현재 E/F보다 압도적으로 나아진 차이가 설명 없이 보임

기준을 못 넘으면 “완성안”으로 보여주지 않고 더 다듬는다.
