## 1. 절대 규칙 — 어기면 그 바퀴는 무효다

### 1.1 계약 (검수에서 정정된 것들 · `V12-REVIEW.md` 근거)

| # | 규칙 | 왜 |
| --- | --- | --- |
| C1 | **커버는 `coverageAt(s,id,aimZone)`의 반환값으로만 그린다.** shape로 추정하지 않는다 | 십자를 모서리에 놓으면 5칸이 아니라 `[0,1,3]`. `expanded`면 넓어지고 `patience` 성장이면 1칸으로 강제된다 |
| C2 | **연결은 스택 순서상 앞뒤 `aimZone`의 동일/8방향 인접이다.** 카드가 물리적으로 닿는 것이 아니다 | `0→4→8`은 2연결, `0→8→4`는 1연결. 순서가 곧 메커닉이다. 순번·메인/지원 구분을 지우는 표현 금지 |
| C3 | **`damageRate`는 배율이다. 예상 HP 피해로 그리지 않는다** | 실제 피해는 `playV10Action`에서 유물·정타·판정을 거쳐 나온다. UI가 공식을 복제하면 어긋난다 |
| C4 | **읽기 등급은 0/1/2다.** `READ_THRESHOLDS`의 2/4는 관찰 **점수** 임계값이다 | 낮은 등급은 숫자를 감출 뿐, **0%라고 단정하지 않는다** |
| C5 | **공개된 정보로만 시각·ARIA·소리를 만든다** | `probabilityBounds`가 감춘 정확값이 음영·라벨·효과음으로 새면 안 된다 |
| C6 | **엔진 공식을 UI에서 다시 구현하지 않는다.** 기존 함수를 호출해 읽는다 | 표시와 실제 계산이 갈라지는 것이 이 저장소의 반복 고장이다 |
| C7 | **`!important` 선언은 레이어 우선순위가 반대다.** 일괄 `@layer` 래핑 금지 | 래핑하면 우선순위가 뒤집힌다. 컴포넌트를 이관할 때 그 컴포넌트만 정리한다 |

### 1.2 절대 금지

- `main`에 push하지 않는다. 배포하지 않는다. **작업 브랜치에만 push한다.**
- 테스트를 건너뛰거나 비활성화하거나 임계값을 완화해 통과시키지 않는다.
- 검증하지 않은 것을 검증했다고 쓰지 않는다. "마스터피스에 도달했다"를 문서에 쓰지 않는다.
- 게임 규칙·확률·피해·카드 수치·런 구조를 바꾸지 않는다. **표현 계층만** 다룬다.
- 빈 커밋·재오픈으로 CI를 흔들지 않는다.
- `V4CanvasSprite` 60Hz 재생, Adaptive Performance 예산, GM09/GM10 Outcome Director를 되돌리지 않는다.

### 1.3 `loop/PROMPT.md`에 대한 예외

| 원 규칙 | 이 작업에서 |
| --- | --- |
| `git push` 금지 | **작업 브랜치 push는 허용.** `main` push와 배포는 여전히 금지 |
| INBOX에서 하나만 고른다 | INBOX 10번이 이 작업이다. 구체 항목은 `V12-PROGRESS.md`에서 고른다 |

## 2. 한 바퀴의 단위

> **한 바퀴 = 한 단계(P*)가 아니라, 한 단계 안의 슬라이스 하나.**

P3 전체를 한 바퀴에 끝내려 하면 반드시 실패한다. `V12-PROGRESS.md`의 **체크박스 한 줄**이 한 바퀴다.

### 2.1 순서

```
① 읽기(§0)  →  ② 이번 슬라이스 하나 고르기  →  ③ 결정 게이트 확인(§3)
   →  ④ 실패하는 검사부터 쓰기  →  ⑤ 구현  →  ⑥ 검사 통과 → 커밋
   →  ⑦ 브라우저로 실제 확인 + 캡처를 눈으로 읽기  →  ⑧ 수정 있으면 후속 커밋
   →  ⑨ PROGRESS·STATUS 갱신 → 커밋  →  ⑩ push  →  ⑪ 다음 바퀴 한 줄 남기기
```

⑥이 ⑦보다 앞이다. 바퀴는 도중에 끊길 수 있고, 커밋 없는 작업은 사라진다.

### 2.2 브라우저 확인은 선택이 아니다

화면이 있는 것을 만들었으면 **반드시 실행해서 캡처하고 그 이미지를 직접 읽는다.**
코드가 도는 것과 화면이 괜찮은 것은 다른 문제다.

```sh
pnpm install --frozen-lockfile && pnpm dev          # 127.0.0.1:5177
# 390×844 / 844×390 / 1440×900 세 뷰포트
# 캡처는 docs/design/v12/shots/<단계>-<슬라이스>-<뷰포트>.png
```

### 2.3 커밋 메시지

```
<type>(v12-P<n>): <무엇을 했는가>

왜 이 슬라이스인가 / 무엇을 검증했고 무엇을 못 했는가 / 다음 슬라이스
```

## 3. 결정 게이트 — 막히면 멈추고 묻는다

`V12-DECISIONS.md`의 D1~D8 중 **아직 답이 없는 항목에 의존하는 슬라이스는 시작하지 않는다.**

| 단계 | 필요한 결정 |
| --- | --- |
| **P0** | **없음.** 지금 바로 시작할 수 있다 |
| P1 | D1(시각 방향) |
| P2 | D1, D3(이름), D5(준비 칩) |
| P3 | D1, D2(커버 표현), D4 |
| P4~P8 | D1, D6(배포 묶음) |

막혔을 때:
1. **지어내지 않는다.** 임의로 정하고 진행하면 나중에 전부 버린다.
2. `V12-PROGRESS.md`의 「막힌 곳」에 한 줄 적는다.
3. 사용자에게 **무엇이 왜 막혔고 선택지가 무엇인지** 한 번만 보고하고 그 바퀴를 끝낸다.
4. 같은 질문을 반복해 올리지 않는다.

**결정 없이 할 수 있는 일이 남아 있으면 그걸 먼저 한다.** P0 슬라이스가 대표적이다.
