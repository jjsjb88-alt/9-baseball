# STATUS

> 매 바퀴가 끝날 때 갱신한다. 사실, 검증 결과, 다음 한 가지를 짧게 남긴다.

## 현재 상태

- `docs/DESIGN.md`가 코어 감정, READ → BET → REVEAL → IMPACT 흐름, 공용 엔진·정보 비대칭·인간 검증 원칙과 명시적 금지사항을 제품 기준으로 고정한다.
- CQ/PQ 공용 판정 엔진이 `src/game/showdown-engine.js`로 분리되어 게임 본체와 테스트가 같은 모듈을 import한다.
- 역할 선택 화면에서 성장·정규 이닝을 건너뛰고 즉시 한 타석만 진행하는 `CORE TEST`에 진입할 수 있다.
- 한 타석 종료 뒤 네 가지 재미 검증 질문에 답하면 결과가 브라우저 로컬 저장소에 누적되고 JSON으로 내려받을 수 있다.
- 코어 테스트 질문·결과 생성·로컬 저장소 읽기/추가·JSON 직렬화가 `src/game/core-test-results.js` 순수 모듈로 분리되어 UI와 테스트가 같은 경로를 사용한다.
- Random / MaxProb / Pattern / PowerSpam 네 고정 시드 정책봇이 실제 CQ/PQ와 PUBLIC/TRUE INTENT 공용 모듈을 사용하며 지배전략 회귀를 검사한다.
- POWER는 정확한 READ에서만 PQ 보너스를 받고, 오독 시 더 큰 CQ 대가를 치른다. 실제 POWER 존 카드도 이 경로에 연결되어 있다.
- 프로덕션 빌드는 애플리케이션 코드와 외부 의존성을 별도 청크로 분리해 500 kB 초과 청크 경고 없이 생성된다.
- happy-dom과 Testing Library로 실제 React 화면을 렌더링해 튜토리얼 건너뛰기 → `CORE TEST` 진입 → 한 타석 종료 → 네 문항 저장 → 다음 플레이어 → JSON 다운로드를 클릭 회귀 검사한다.
- 여러 플레이어가 내려받은 누적 JSON은 `pnpm run report:core-test -- <파일...>`로 합칠 수 있으며, 완전한 응답만 중복 없이 집계해 3명 목표와 네 재미 신호를 보고한다.
- CORE TEST 보고서의 중복 판정은 JSON 객체의 키 순서와 무관해, 같은 응답을 재포맷한 누적 파일도 한 번만 집계한다.
- CORE TEST 보고서는 앱이 생성한 version 1 내보내기 스키마 전체를 검증하며, 답변만 넣은 임의 객체나 손상된 시각·투구 기록을 실제 인간 응답으로 세지 않는다.
- CORE TEST 보고서는 최상위·답변·투구 기록의 허용 필드와 실제 네 구종 ID까지 정확히 검사해, 숨은 필드나 앱에 없는 구종이 섞인 JSON을 앱 내보내기로 인정하지 않는다.
- CORE TEST 보고서는 완료된 한 타석에 투구 기록이 최소 1개 있어야 한다고 검사해, `pitchesSeen: []`인 불가능한 수동 응답을 인간 결과로 세지 않는다.
- CORE TEST 로컬 저장소도 보고서와 같은 앱 스키마로 응답을 걸러, 손상된 배열 항목이 화면의 3인 카운트·후속 저장·JSON 다운로드에 포함되지 않는다.
- CORE TEST 초기 저장소 읽기가 실패하면 역할 선택 화면에 접근 가능한 오류와 `다시 불러오기` 경로가 나타나며, 복구 뒤 기존 결과 건수를 되살린다.
- CORE TEST 결과 저장이 실패하면 완료 설문 안에 오류가 즉시 표시되며, 기존 답변과 메모를 유지한 채 다시 저장할 수 있다.
- CORE TEST JSON 내보내기가 실패하면 역할 선택 화면에 오류가 즉시 표시되며, 저장된 결과를 유지한 채 같은 버튼으로 다시 시도할 수 있다.
- CORE TEST JSON 내보내기가 Blob URL 생성 뒤 클릭 단계에서 실패해도 임시 링크와 Blob URL을 정리하고 같은 버튼으로 다시 시도할 수 있다.
- 일반 피드백 저장이 실패하면 열린 모달 안에 접근 가능한 오류가 나타나며, 평점과 입력을 유지한 채 같은 제출 버튼으로 다시 시도할 수 있다.
- 관리자 피드백 불러오기가 실패하면 내보내기 패널 안에 접근 가능한 오류와 `다시 불러오기` 경로가 나타나며, 실패 상태에서는 잘못된 JSON 다운로드를 막는다.
- 인간 3인 플레이테스트의 실제 응답 수집은 아직 진행하지 않았다.

## 마지막으로 완료한 한 가지

- 관리자 피드백 불러오기 실패를 열린 내보내기 패널 안에 표시하고, 재시도 성공 전에는 다운로드를 막는 경로를 회귀로 고정했다 (`c1f21ab`).

## 검증 결과

- 자동 검사: 전체 `pnpm test` 20/20, `pnpm run test:policy`, `pnpm run build`, `git diff --check` 통과.
- 회귀 확인: 관리자 피드백 목록을 한 번 불러오지 못하면 열린 패널의 `role="alert"` 오류가 보이고 다운로드가 비활성화된다. `다시 불러오기`가 성공하면 실제 1건과 JSON 내용이 복원되고 다운로드가 다시 활성화된다.
- 정책 확인: PowerSpam/최선 비파워 TB/PA 1.022, 세 지배전략 기준 모두 통과.
- 확인하지 못한 것: 로컬 앱은 `http://localhost:5174/`에서 기동했지만 브라우저 연결 복구 절차와 사용 가능 유형 조회 결과가 0개라 관리자 내보내기 패널의 실제 픽셀·레이아웃과 스크린샷 QA를 수행하지 못했다.
