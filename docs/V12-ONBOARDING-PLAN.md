# V12 — 초보 이해도 기획안 · "어렵다"가 아니라 "모르겠다"를 고친다

> 근거: 2026-09-22 플레이테스트 피드백(효나). 이 문서는 계획이며 **아직 구현하지 않았다.**
> 우선순위 판단과 범위 승인은 사용자 결정 사항이다.

## 0. 한 줄 판정

**난이도 문제가 아니라 전달 문제다.** 규칙은 이미 단순한데, 화면이 그 규칙을
플레이어가 배우는 순서로 내놓지 않는다. 밸런스를 낮추지 않고 전달 순서만 고쳐서 해결한다.

## 1. 받은 피드백 (원문)

| 시각 | 내용 |
| --- | --- |
| 08:37 | 비니닝 겜 1스테이지에서 쥬금 / **너무 복잡 어려움** |
| 09:05 | 이전보다는 훨 **게임느낌이 나** (이펙트 때문인거같기도) |
| 09:05 | 근데 **야구 초보나 겜초보에겐 좀더 직관적이어야 할듯** |

사용자 해석: **"방법 자체가 어렵지는 않은데 이해하기 어려운 것 같다."**

### 이 피드백이 말하는 것 / 말하지 않는 것

- 말한 것: 연출·게임감은 개선됐다. 1스테이지에서 죽었다. 시스템을 이해하지 못했다.
- 말하지 않은 것: 밸런스가 세다. 시스템이 많아서 잘못됐다. 연출을 줄여라.
- 따라서 **밸런스 수치, 카드 수, 시스템 개수는 이 기획안의 대상이 아니다.**

## 2. 진단 — 코드에서 확인한 원인 6가지

### 원인 1. MAIN RUN에는 튜토리얼이 아예 실행되지 않는다 (가장 큰 원인)

`src/duel/App.jsx:719`

```js
useEffect(()=>{if(!showBattle||isV10||s?.phase!=='battle'||tour.open||tourDismissed.current)return; ... setTour({open:true,step:0});},[...]);
```

`isV10`이면 **즉시 return**한다. `TOUR_STEPS` 6단계 웰컴 가이드(`App.jsx:89–96`)는
구형 튜토리얼 덱에서만 뜨고, 실제로 사람이 플레이하는 MAIN RUN에서는 **한 번도 뜨지 않는다.**

타이틀 화면(`App.jsx:799`)의 기본 CTA는 `새 런 시작`(MAIN RUN)이다.
즉 **처음 온 사람은 가장 깊은 시스템에 가이드 0으로 입장한다.** 1스테이지 사망은 당연한 결과다.

### 원인 2. 타이틀에서 이미 선택지가 3겹이다

한 화면에 MAIN RUN 2버튼 + 튜토리얼 4덱 버튼 + 비교용 시드 입력이 동시에 있다.
게임 초보는 "무엇부터 눌러야 하는지"부터 막힌다. 튜토리얼은 `아래 네 덱은 규칙만 익히는
모드입니다`로 **부차적으로** 소개돼 있어 선택될 이유가 약하다.

### 원인 3. 핵심 판단 화면의 어휘가 영어 게임 용어다

`BattleReadout.jsx`가 한 번에 내놓는 라벨: `BATTLE READOUT` / `COVER 5/9` / `PRESSURE 80% HP` /
`COST 3/4` / `CONNECT` / `BREAK` / `MAIN`. 여기에 `damageRate`, `precisionPressure`가 수치로 붙는다.

야구 초보는 **9존·커버·적중**이라는 이 게임 고유 규칙을 모르고,
게임 초보는 **COVER/COST/효율**이라는 덱빌딩 로그라이트 문법을 모른다.
피드백은 이 두 사람을 동시에 지목했다.

### 원인 4. 이 게임의 제1규칙이 판단 순간에 적혀 있지 않다

**"커버한 칸에 공이 오면 안타"** 는 이 게임 전체를 지탱하는 한 문장인데,
도움말 모달(`App.jsx:818`) 본문 안에만 있다. 존을 고르는 순간의 화면에는 없다.
플레이어는 칸을 고르면서도 그 칸이 무슨 의미인지 모른 채 고른다.

### 원인 5. 숫자가 동시에 9개 뜨고, 어느 것도 "그래서 뭐"를 말하지 않는다

스윙 화면에는 BattleReadout 3미터 + 존 보드 가이드(`stack-direct-tap.js:89 setGuide`)의
카운트·효율 스트립 + StackBoard의 ①②③④/CONNECT·BREAK + 카드별 커버 미리보기가
**같은 시각 비중으로** 동시에 있다. 요약 문장이 없다.

### 원인 6. 코치가 딱 2타석 뒤에 사라진다

`App.jsx:800`의 `coach={b.turn<=2}`, `b.turn<=2&&<DecisionDebrief …>`, `stack-discovery` 안내 모두
**타석 2회까지**다. 그런데 스택·순서·CONNECT를 실제로 쓰기 시작하는 시점은 그보다 뒤다.
가장 어려운 개념이 등장하는 순간에는 설명이 이미 꺼져 있다.

## 3. 설계 원칙 4개

1. **시스템을 지우지 않는다. 등장 순서만 바꾼다.** 복잡도는 이 게임의 값어치다.
2. **야구말 먼저, 게임말 나중.** 한글 야구 표현이 1차 라벨, 영어는 보조 표기.
3. **숫자 아홉 개보다 문장 한 줄.** 요약 한 줄이 기본, 수치는 펼쳐 보는 상세.
4. **읽어서 배우지 않고 해봐서 배운다.** 설명 모달을 키우지 말고 첫 타석을 설계한다.

## 4. 해결안 A–H

각 항목은 `문제 → 변경 → 화면 → 수용 기준` 순서다.

### A. 첫 타석 가이드를 MAIN RUN 안으로 (P0 · 가장 큰 효과)

- **문제**: 원인 1.
- **변경**: `isV10` 제외를 없애고, MAIN RUN 전용 **스크립트 첫 타석**을 만든다.
  구형 6단계 투어를 그대로 붙이지 않는다. MAIN RUN 문법으로 다시 쓴다.
- **화면**: 4스텝, 각 스텝은 실제 조작 1회를 요구한다.

  | 스텝 | 요구 조작 | 한 줄 설명 |
  | --- | --- | --- |
  | 1 | 9존에서 칸 하나 탭 | "투수가 여기로 올 것 같다. 그 칸을 고릅니다." |
  | 2 | 카드 1장 그 칸에 놓기 | "카드를 놓으면 그 카드가 **커버**하는 칸이 켜집니다." |
  | 3 | 스윙 | "공이 켜진 칸에 오면 **안타**입니다." |
  | 4 | 결과 읽기 | "투수 HP가 깎였습니다. HP를 0으로 만들면 강판입니다." |

- **첫 공은 스크립트로 안타를 보장한다.** 규칙을 글로 읽히지 않고 몸으로 한 번 통과시킨다.
  (엔진 난수를 건드리지 않고, 온보딩 플래그일 때만 첫 투구 존을 커버 안으로 고정한다.)
- **스택·순서·CONNECT는 이 4스텝에서 언급하지 않는다.**
- **수용 기준**: 새 저장으로 `새 런 시작` → 가이드 자동 등장, 4스텝 완주 시 안타 1개 확보.
  `건너뛰기` 1회로 완전 종료되고 다시 뜨지 않는다. 기존 런 이어하기에는 뜨지 않는다.

### B. 용어를 야구말로 바꾼다 (P0)

- **문제**: 원인 3.
- **변경**: 1차 라벨을 한글 야구 표현으로, 영어는 작은 보조 표기로 병기한다.

  | 현재 | 1차 라벨 (신규) | 보조 표기 |
  | --- | --- | --- |
  | `COVER 5/9` | **노리는 칸 5 / 9** | COVER |
  | `PRESSURE 80% HP` | **한 방 위력 80%** | PRESSURE |
  | `COST 3/4` | **카드 3장 사용** | COST |
  | `CONNECT` | **이어치기** | CONNECT |
  | `BREAK` | **끊김** | — |
  | `MAIN` | **본 스윙** | MAIN |
  | `BATTLE READOUT` | **이번 스윙 요약** | — |
  | `READ` | **투수 읽기** | READ |
  | `STACK` | **겹쳐치기** | STACK |

- 영어 표기를 삭제하지 않는다. 재방문 플레이어와 기존 테스트 계약을 깨지 않기 위해
  `aria-label`과 데이터 속성은 현행 키를 유지하고 **표시 텍스트만** 바꾼다.
- **수용 기준**: 스윙 화면 캡처 1장에서 초보가 모르는 영어 단어가 1차 라벨에 0개.

### C. 한 줄 요약 판정 (P0)

- **문제**: 원인 4·5.
- **변경**: BattleReadout 최상단에 **생성된 한 문장**을 넣고, 3미터는 그 아래 접이식 상세로 내린다.
- **문장 틀**: `{어디}를 노립니다. 맞으면 {결과}, 위력 {값}. 카드 {n}장.`
  - 예: "가운데 세로 3칸을 노립니다. 맞으면 안타, 위력 보통(80%). 카드 2장."
  - 예: "한 칸에 겁니다. 맞으면 장타, 위력 최대(100%). 카드 1장."
- 기본은 요약만 펼침. 상세(3미터 + CONNECT 계산)는 **한 번 열면 그 런 내내 기억**한다.
- **수용 기준**: 요약 문장과 3미터가 같은 `stackPlan`을 읽는다(수치 불일치 금지).
  요약만 읽고도 "맞으면 뭐가 되는지"를 답할 수 있다.

### D. 점진 해금 — 첫 경기에는 시스템 3개만 (P1)

- **문제**: 1경기부터 준비/스윙/지켜보기 3행동 + 스택 4장 + 순서 + CONNECT + 유물 + 시설이 전부 열려 있다.
- **변경**: 신규 플레이어에 한해 아래 순서로 연다. 숙련자(런 1회 완주 이력)는 전부 열린 상태로 시작한다.

  | 해금 시점 | 열리는 것 |
  | --- | --- |
  | 런 시작 | 스윙(카드 1장) · 한 구 지켜보기 |
  | 첫 안타 이후 | 준비하기 |
  | 2번째 경기 | 겹쳐치기 2장 (1회성 3줄 안내) |
  | 3번째 경기 또는 2막 | 순서 변경 · 이어치기(CONNECT) · 4장 |

- **밸런스를 바꾸지 않는다.** 카드와 수치는 그대로고, 초반에 **보여주지 않을 뿐**이다.
  잠긴 기능은 숨기지 말고 **잠금 표시 + 해금 조건**을 적는다(목표가 생긴다).
- 저장 스키마에 `onboarding:{unlocked:[],seen:{}}`를 **추가만** 한다. 기존 저장은 전부 해금으로 읽는다.
- **수용 기준**: 신규 저장 1경기에서 화면에 동시 존재하는 조작 개념이 3개 이하.
  기존 저장 이어하기에서 잠김이 0개.

### E. 코치를 타석 수가 아니라 이해도로 끈다 (P1)

- **문제**: 원인 6.
- **변경**: `b.turn<=2` 게이트를 **개념별 카운터**로 교체한다.
  개념(스윙/준비/지켜보기/겹쳐치기/순서/이어치기)마다 **성공적으로 2회 사용**할 때까지 코치 문구를 유지하고,
  그 뒤 자동으로 꺼진다. 카운터는 런이 아니라 프로필 단위로 저장한다.
- **수용 기준**: 겹쳐치기를 처음 쓰는 타석이 5번째 타석이어도 코치 문구가 나온다.
  같은 개념을 2회 성공한 뒤에는 나오지 않는다.

### F. 패배 화면이 원인을 말한다 (P1)

- **문제**: 1스테이지에서 죽고 나면 무엇을 잘못했는지 알 수 없다. 재도전 동기가 사라진다.
- **변경**: 패배 화면에 **한 줄 원인 + 한 줄 처방**을 넣는다. 통계는 그 아래.
  - "3아웃 동안 투수 HP를 {x}만 깎았습니다. 필요한 값은 {y}."
  - "다음엔 카드를 적게 쓰고 한 칸에 거는 스윙을 섞어보세요. 위력이 100%가 됩니다."
- 처방은 그 런의 실제 기록(평균 카드 수, 커버 폭, 헛스윙 비율)에서 고른다. 랜덤 격언 금지.
- **수용 기준**: 패배 3종(삼진 과다 / 커버 과다·위력 부족 / 볼카운트 낭비)에 서로 다른 처방이 나온다.

### G. 타이틀 정리 (P1)

- **문제**: 원인 2.
- **변경**: 1차 화면은 `새 런 시작` / `이어하기` 2개만. 튜토리얼 4덱과 비교용 시드는
  `연습 · 고급` 접이식으로 내린다. 처음 여는 플레이어에게는 `새 런 시작` 하나만 강조한다.
- **수용 기준**: 첫 진입 화면의 누를 수 있는 요소 3개 이하(시작 / 이어하기 / 고급 펼치기).

### H. 효율 %를 체감 수치와 함께 (P2)

- **문제**: `100/80/65/50%`와 `CONNECT +7%p`는 야구 감각이 아니라 계산이다.
- **변경**: 비율 옆에 **예상 피해 실수치**를 같이 적는다. "위력 80% · 예상 피해 12 (단독이면 16)".
  초보는 실수치를 읽고, 숙련자는 비율을 읽는다.
- **수용 기준**: 표시 실수치가 엔진 `relicPlan.damageRate` 경로와 같은 값에서 나온다.

## 7. 검증 계획

### 자동
- 전체 `pnpm test` + 신규 회귀 테스트 + `pnpm build`.
- `node scripts/zone-report.js 30`로 온보딩 변경이 확률 경로에 새지 않았음을 확인(수치 동일해야 함).

### 사람 (이게 진짜 기준이다)
P0 배포 후 **같은 테스터에게 새 저장으로 1경기**를 맡기고, 도움말을 열지 않은 상태에서 3개를 묻는다.

1. 안타는 어떻게 나오나요?
2. 카드를 2장 쓰면 무엇이 손해인가요?
3. 방금 왜 졌나요(또는 이겼나요)?

**통과 = 3개 모두 도움말 없이 답함.** 하나라도 막히면 그 개념이 P0에서 실패한 것이고,
그 지점만 다시 고친다. 완주율·승률은 이번 판정 기준이 아니다.

## 8. 하지 않는 것

- 난이도·확률·HP·카드 수치 하향 — 피드백은 "어렵다"가 아니라 "모르겠다"였다.
- 스택·순서·CONNECT 시스템 삭제 또는 축소 — 이 게임의 값어치다.
- 연출 축소 — "게임느낌이 난다"는 호평을 받은 부분이다.
- 도움말 모달 증량 — 안 읽는다. 읽게 만들 게 아니라 안 읽어도 되게 만든다.

  이번 피드백은 연출을 호평하고 **이해도**를 지적했다. 아트 루프와 온보딩 중
  무엇을 먼저 할지는 **사용자 결정 사항**이다. 이 문서는 아트 기준을 취소하지 않는다.
