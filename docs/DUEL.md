# HOMEBOUND — 선수·타순과 행동 카드 분리

## 현행 v6: 세 런 성장 · 2026-09-11

이 절과 아래 v5의 기본 야구 규칙이 현행이다. 충돌하면 v6 우선. 기존 src/duel에 통합했으며 자동시뮬도 같은 engine.js를 호출한다. PUBLIC은 실제 코스 분포이고 pending 코스/판정 난수는 공 준비 때 고정한다. 과거 CQ/PQ·TRUE INTENT 및 ROOKIE/ADAPTER/FOX 전체 엔진을 복원한 버전은 아니다.

### 성장 및 자원 수명

- **기다림/patience:** 살아남은 루킹 스트라이크마다 +1, 타석당 최대 2. 볼/헛스윙/파울/세 번째 스트라이크는 충전하지 않는다. 사용 예약 시 타격 범위를 선택한 1존으로 줄인다. Lv.1/2/3은 중첩당 파워 +24/+36/+48. BASIC도 장타 가능. 스윙하면 성공 여부와 무관하게 전량 소모하며 취소/미리보기는 소모하지 않는다. 새 타석/경기에서 초기화.
- **연결/relay:** 실제 기존 주자를 진루시키는 성공 희생 번트이고 3아웃 미만일 때 다음 타석 사인 획득. Lv.1/2/3 타격 +10/+20/+30, 안타 시 기존 주자 +1/+1/+2베이스. 타자에게 추가 진루를 주지 않는다. 다음 타석의 파울/헛스윙 중에는 유지, 그 타석 종료/새 경기에서 소멸. 빈 베이스·3아웃·번트 파울로 획득 불가.
- **행운/fortune:** 소유 후 땅볼 안타 +1, 바가지 안타 +2. Lv.3은 각각 +2/+3. 중전안타는 충전하지 않는다. 최대 6, 다음 경기로 보존. Lv.1 소비 3, Lv.2/3 소비 2. 예약 후 비홈런 안타 때 타자와 기존 주자 +1베이스. 미적중에는 자원과 예약 유지, 홈런에는 자원 보존. 타석 종료 시 예약 해제. 사용한 안타는 다시 충전하지 않는다. 추가 진루는 수비 혼선으로 기록하며 안타 자체의 총루 수를 부풀리지 않는다.

기다림과 행운 예약은 상호 배타적이며 예약 중 희생 번트는 막는다. 성장 자원/순위/활성 조건은 저장 검증 대상이다. 실제 공이 표시된 커버에 들어오면 성장 유무와 무관하게 안타다.

### 보상·저장·검사

각 승리 후 `chooseCard(state, kind 또는 'skip', growthKey)`가 성장 1단계와 카드 획득을 함께 확정한다. 성장 선택 전 확정 불가. 성장 변경 시 UI의 이전 카드 선택을 해제한다. 같은 성장 최대 3단계 또는 혼합, 선택한 성장의 시그니처 카드가 후보에 추가된다.

state.version=6 / SAVE_KEY=`9zone-growth-v6`. growth/history/fortune/growthStats와 battle의 waitCharge/relayPending/relayActive/growthMode를 저장한다. 과거 저장은 보존하고 읽어 덮어쓰지 않는다.

`tests/duel-growth.test.js` 14개와 `tests/duel-growth-ui.test.jsx` 5개가 보상 중복·리로드·소모·모든 존/단계 적중 보장·확률 정규화·주자 ID·경기 간 수명을 검사한다. 전체 87검사. `pnpm report:growth`는 세 덱/세 고정 성장 경로/각 30시드의 270런이며 매 행동 저장 검증을 수행한다. 정책은 공개 정보만 사용하지만 인간의 선택을 재현하지 않는다.

브라우저: 실제 클릭으로 첫 경기 3득점 승리 → 기다림+릴리스 간파 획득 → 두 번째 경기 루킹 스트라이크 충전 → 한 존 BASIC 파워 +24 예고 → 미적중 후 충전 0과 같은 타자 유지 확인. 성공 타격/연결/행운 효과는 자동 엔진·React 검사로 확인했고 모든 경로를 수동 완주한 것은 아니다.

현재 연결 경로가 자동 정책에서 약하다. 효과 숫자만 올리기 전에 아웃 투자 대비 다음 타석 기대 진루와 카드 기회비용을 검토한다. 3포즈 자산/650ms 연출을 유지했으며 고급 타구별 아트와 30분 인간 플레이 검증은 남았다.

## 현행 v5: 성공한 읽기를 배신하지 않는다 · 2026-09-10

아래 v3/v2 기록보다 이 절이 우선한다. 진입점 src/main.jsx → src/duel/App.jsx 유지. 최신 v4 UI를 fast-forward한 뒤 기존 엔진에 통합했고 별도 게임 소스를 만들지 않았다.

### 핵심 계약

- **스윙 커버 안의 실제 투구 = 안타 확정.** 중앙에 선택한 존뿐 아니라 초록색으로 약속한 범위 전체에 적용한다. BASIC도 동일하다. 범위를 맞힌 뒤 헛스윙·파울·아웃으로 다시 굴리지 않는다.
- 타자 타격/파워/행운과 투수 변화/구위/제구는 안타 종류만 조절한다. 땅볼 안타, 중전안타, 행운의 바가지 안타, 2루타, 홈런. 첫 세 종류는 현재 모두 단타/동일 기본 진루이며 타구 애니메이션도 공통이다.
- 희생 번트는 설명에 명시된 예외: 스트라이크에서 희생 70%/파울 30%, 2스트라이크 번트 파울 삼진, 3아웃 시 득점 없음.
- 범위 밖은 파울 또는 헛스윙. 일반 파울은 2스트라이크 이후 스트라이크 증가 없음. 지켜본 볼은 4볼 볼넷, 스트라이크는 3개면 삼진. 볼넷은 연결된 강제 주자만 이동한다.
- 준비는 타석 전체 최대 2회, 공 소비 없음. 다음 공 확인 시 카드 1장. 타석 종료 뒤 다음 타자 입장 시 손패 5장까지 보충. BASIC은 카드가 없어도 가능.

### 덱 / 공 / 스탯

BUILDS에 몸쪽 장타/바깥 연결/끈질긴 컨택의 서로 다른 12장 덱, 타격/파워/행운, 4숙련존이 정의돼 있다. 선수 타순별 작은 스탯 편차와 집중 버프도 표시한다. 스탯은 0–100 스케일의 게임 추상화다.

세로/가로/십자/한 칸 커버. 스탯 비교는 engine.js matchup/hitProfile, 안타 보장 계약은 swingOdds. 넓은 범위는 (칸수-1)×7 파워 페널티, 숙련존은 타구 질/파워 +12. 코스 조정으로 범위를 확장해도 파워 페널티를 적용한다. BASIC/커트는 단타만 나온다.

투구 코스 분포는 baseIntent. 루키 바깥 선호/2스트라이크 몸쪽, 싱커 낮음, 외야 후퇴 장타 억제, 마무리 이전 노림 반대 열. 보스용 컨택 문턱은 아직 없음. CQ/PQ 옛 엔진과 병렬 판정하지 않으며 기존 ROOKIE/ADAPTER/FOX 전체를 복원했다고 주장하지 않는다.

PUBLIC 확률 그대로 zone 0–8와 존 밖 9를 추첨. 카드 드로우와 투구 RNG는 분리돼 같은 seed의 세 덱 첫 투구는 같다. 카운트/과거 행동이 달라지면 이후 투구 분포는 달라진다. pitchSeed와 pending은 로컬 저장되므로 보안상 비공개 서버가 아니라 UI에서 감춘 게임 상태다.

릴리스 간파만 현재 공의 높이 또는 볼 여부를 알려주고 확률을 조건부로 갱신한다. 미리보기는 숨은 roll/zone을 읽지 않으며 현재 코스 확률×커버로 적중 확률, 적중 조건부 안타 종류 비율을 계산한다.

### 상태 / 재입력 방지

map → battle → pitch → battle (같은 타자), 또는 battle → between → battle (다음 타자).
목표 득점이면 reward/won, 3아웃이면 lost. 결과 노출 후엔 phase 게이트와 UI lock 모두 추가 투구를 차단한다. pending을 미리 확정하여 존 선택/카드 미리보기/리로드 재추첨 방지. 저장 key 9zone-zones-v5, version 5. 구 v3 저장 보존.

### 검사와 관찰

- pnpm test: 68개. 전 커버/스윙/덱/샘플 난수에서 안타 보장, 안타 종류 분포, 숨은 정보 비노출, 플레이어/카드 보존, 볼넷 강제진루, 파울·삼진·희생, 저장, 전체 런, React 입력 경계.
- pnpm report:zones: 현행 엔진과 public-only planAction 공유. 첫 투수 100시드 결과는 STATUS 참고. 학습/재미를 모델링하지 않는다.
- pnpm test:policy는 레거시 엔진 검사. CI는 기존 회귀에 더해 zone-report 30시드 실행.
- 브라우저: 관찰 → 가로 커버 100% → 중전안타 확인. 모바일 메뉴/격자/결과 확인.

남은 한계: 넓은 커버 강세, 자동 baseline의 볼넷 0회, 타입별 단타 진루 차이 없음, 공통 3포즈와 연출, 30분/인간 재미 미검증. 이번 변경은 로컬이며 GitHub 배포는 별도 요청 때 진행한다.

## 최우선 현재 규칙: version 3 / 2026-09-09

사용자는 ‘정타를 두 번 내는 것이 야구인가?’라고 지적했다. 이전 v2는 행동 카드를 선수처럼 베이스에 놓고, 타격 직후 타석 번호만 올려 연속 공격처럼 보였다. **이 구조를 폐기했다. 아래 v2의 베이스=덱 규칙은 더 이상 적용하지 않는다.**

- LINEUP: 9명의 고정 선수 ID(p1–p9), 이름, 등번호. 현재 타자와 베이스 주자는 선수 ID다. cards의 c0… ID와 절대 섞지 않는다.
- 모든 사용 행동 카드는 버린 더미로 이동한다. 출루/득점으로 카드를 잠그거나 손패로 귀환시키지 않는다. 카드 보존은 손패+뽑기+버리기만으로 검사한다.
- 타격 카드 1장 사용 → 투구/스윙 1회 → 타자와 기존 주자 판정 → between 상태. 이 상태에서 playCard/endTurn은 원본 참조를 반환하며 추가 행동을 거부한다.
- between은 저장되는 게임 상태다. 애니메이션이 끝나도, 새로고침해도 자동으로 다음 타석을 시작하지 않는다. ‘다음 타자 입장’ 버튼이 advanceBatter를 호출해야만 다음 순번으로 이동한다.
- 다음 타자 입장에서 카운트/노림/준비/사인을 초기화하고 손패를 5장까지 보충한다. 9번 이후 1번으로 순환한다. 주자와 현재 타자가 중복되는 저장을 거부한다.
- 루킹 삼진/타격 아웃도 동일한 타석 종료 경계를 사용한다. 3아웃이나 목표 달성 시에는 다음 타자 대신 승부 결과로 이동한다.
- 준비 카드는 타석당 2회, 투구/스트라이크를 소비하지 않는다. 관찰·준비를 연계한 뒤 스윙 한 번. 실제 투구 수는 타격/지켜보기에서만 늘어난다.
- v2 대주자 교체→호흡 고르기, 딜레이드 스틸→히트앤드런 사인. 행동 카드 자체가 선수로 교체되는 모순을 제거했다. 사인만으로 주자가 움직이지 않고, 이후 안타의 진루에만 적용된다.
- UI에 9명 타순, 현재 타자 이름·등번호, 베이스 주자 이름, 타석 종료 결과와 다음 타자 이름을 표시한다. 종료 후 타자 스프라이트가 사라지고 다음 선수 입장 때 다시 등장한다.
- 새 저장 키 9zone-lineup-v3. 이전 키는 유지하며 잘못된 의미의 v2 저장을 자동 변환하지 않는다.

### 검증

v3 신규 17개 + 보존 코드 41개 = 전체 58개 검사. 핵심은 같은 타석의 두 번째 공격 거부, 결과 화면 새로고침 후 입력 차단 유지, 서로 다른 타자의 같은 타격 카드 사용, 9→1 타순 순환, 선수/카드 영역 혼입 거부다. 실제 React 클릭으로 4승부/3보상/완주를 검증한다. 브라우저에서 1번 강한결 단타→1루 주자 강한결→타격 입력 없음→2번 이민준 입장까지 확인했다.

아직 선수별 그림은 공용 스프라이트에 이름·등번호를 붙인 단계다. 선수별 능력/카드 일러스트/최종 아트는 미완료. 컨택 임계값, 자동 직구 유도, 희생타 진루 등은 덱빌딩용 추상화이지 공식 야구 시뮬레이션이 아니다. 이번 수정은 기본 단위의 일관성과 입력 안전성에 대한 것이며 마스터피스/재미 검증 완료가 아니다. 로컬에만 반영하며 공개 페이지는 별도 배포 전까지 이전 버전이다.

다음 순서: 현재 타자/다음 타자 전환이 플레이어에게 분명한지 관찰 → 선수별 타격 성향이 준비 카드 선택을 실제로 바꾸도록 설계 → 선수별 아트와 연출. 선수와 행동 카드를 다시 합치지 않는다.

## 보존 기록 — v2 (현행 아님)

## 최우선 변경: 2026-09-09 / version 2

사용자는 DUGOUT을 ‘슬더스 스킨’이라고 거절했다. 기능 추가가 아닌 핵심 자원 구조를 변경했다. **현행은 같은 src/duel/App.jsx, engine.js, cards.js에 통합된 HOMEBOUND**다. 아래 DUGOUT v1은 역사 기록이며 구현 지침이 아니다.

핵심 명제: **성공한 카드를 일시적으로 잃고, 다른 카드로 홈에 들여보내 점수와 카드를 함께 돌려받는다.** 베이스는 UI 장식이나 버프 슬롯이 아니라 카드의 실제 저장 위치다.

### 무엇이 달라졌나

- 플레이어/적 HP, 방어, 3에너지, 턴마다 전체 손패 버리기를 제거했다.
- 3아웃 전에 목표 득점. 네 승부의 목표는 2/3/3/4점이며 베이스·카운트에 반응하는 수비가 다르다.
- 타격 성공 시 그 카드 ID가 베이스로 이동. 뽑기/버리기/손패에 동시에 존재할 수 없다. 주자 진루는 동일 ID의 이동이다.
- 득점하면 그 카드가 손패로 복귀. 손패 9장 제한에 걸리면 버린 더미로 복귀한다. 타석 종료 시 손패를 유지하면서 부족한 만큼 5장까지 보충한다.
- 아웃된 타격 카드는 이번 승부 동안 벤치에 묶인다. 새로운 승부는 베이스·벤치까지 전체 덱을 회복한다.
- 작전 카드는 스트라이크 하나를 대가로 한다. 한 타석에 최대 두 번. 컨택 준비, 드로, 주루, 대주자 중 무엇에 카운트를 쓸지 선택한다.
- ‘한 구 지켜보기’는 스트라이크 +1 / 드로 1, 세 번째 스트라이크면 아웃. 작전 카드와 야구 카운트의 결합은 명시적인 전술적 추상화다. 실제 볼/스트라이크·파울을 완전히 재현한다고 주장하지 않는다.
- 기본 컨택+노림이 수비의 요구치 이상이면 확정 안타, 미달이면 아웃. 같은 함수로 득점/아웃/베이스 이동을 미리 계산한다. 숨은 성공률은 없다.
- 수비: 빈 베이스는 직구, 1루 상황은 병살 유도, 득점권은 변화구, 2스트라이크는 결정구. 외야 후퇴는 장타를 단타로 억제한다. 이유와 요구치가 모두 표시된다.
- 2루타로 강타 카드가 잠겼을 때 대주자 카드를 그 베이스에 보내 강타 카드를 회수할 수 있다. 아웃을 지불하지 않지만 카운트와 대주자 카드의 재사용을 포기한다.
- 희생 번트/진루타는 수비 요구치를 무시하지만 아웃 하나를 쓴다. 세 번째 아웃이면 진루와 득점이 모두 무효다.
- 시드에 관계없이 첫 승부의 첫 손패는 동일한 실제 선택을 보여준다. 이후 드로와 다음 승부는 seeded shuffle. 보상은 3회, 시작 덱 12장, 최종 12–15장.

### 특색을 검증할 세 가지 갈등

1. 출루: 당장 안전한 단타로 카드를 베이스에 묶을 것인가, 카운트를 써서 그 카드를 장타로 보낼 것인가?
2. 회수: 대주자로 강타 카드를 먼저 회수할 것인가, 안타를 연결해 점수와 함께 돌려받을 것인가?
3. 희생: 한 아웃과 타격 카드를 벤치에 지불해 주자를 귀환시킬 것인가, 주자를 남겨 주자 불러들이기의 컨택을 높일 것인가?

이는 새 가설이지 재미가 증명된 결론이 아니다. 다음 기능 수를 늘리기 전에 이 갈등을 사용자 플레이에서 관찰한다. 홈런/직구 고정 조합이 모든 상황의 정답이 되는지, 대주자·희생이 실제로 선택되는지, 베이스에 묶인 카드를 플레이어가 기억하는지를 확인한다.

### 검증 및 인수인계

- 새 저장 키 `9zone-diamond-v2`, 상태 version 2. v1 저장 키는 읽거나 지우지 않는다. 이전 구현은 Git 기록 60bde32에서 복원 가능하다.
- src/duel/engine.js 단일 엔진을 UI 미리보기와 QA 탐색기가 공유한다. 총 카드 ID = 손패+뽑기+버리기+벤치+베이스. 모든 행위 뒤 보존 검사를 수행한다.
- 신규 16개 테스트 + 보존 코드 41개 = 전체 57개 통과. 기존 v1 HP 전투용 10개 테스트는 새 규칙의 검사로 교체했다.

- 실제 React 클릭으로 네 승부·세 보상·완주 확인. 브라우저에서 준비→2루타→대주자 회수→주자 불러들이기→득점/카드 복귀/병살 수비 전환을 확인했다. 390px 모바일 배치도 직접 확인했다.
- QA 탐색기 시드 1–10 모두 완주. 탐색기가 미래 드로를 보므로 인간 난이도나 재미의 근거가 아니다. 아직 밸런스/지배 전략 검증을 완료하지 않았다.
- 이미지 파일은 이번에 새로 생성하지 않았다. 기존 도트 구장/3포즈를 재사용하고 베이스 카드·득점/카운트·미리보기·귀환 이벤트를 화면에 통합했다. 최종 아트나 120고유 프레임으로 주장하지 않는다.
- 로컬에서 적용. 이 변경은 아직 GitHub Pages에 재배포하지 않았다. 공개 사이트는 이전 DUGOUT일 수 있다.

다음 우선순위: 같은 손패/베이스 변화만으로 사용자 선택이 실제 달라지는지 관찰 → 카드 회수/희생/준비의 지배 전략 비교 → 베이스 사이 실제 카드 이동과 귀환 연출 → 카드/캐릭터 최종 아트 통일. 30분 분기 런은 이후다. 또 다른 기본 앱을 만드는 대신 현행 소스에 통합한다.

## 핵심 방향

사용자가 원하는 것은 슬더스형 로그라이크 덱빌딩과 고품질 2D 도트 그래픽이다. 이전 LAST LIGHT는 여전히 코스 찍기에 머물렀다. 이번 버전은 **공개된 의도를 여러 카드의 순서와 조합으로 해결하는 전투**다. 코스 선택, PUBLIC/TRUE INTENT의 숨은 차이, 접촉 확률, 숙련존을 사용하지 않는다. 아래 역사 문서를 이유로 이전 구조를 되살리지 않는다.

- 턴당 행동력 3, 손패 5장(최대 10장), 여러 카드 사용 후 턴 종료. 공격은 확정 적중. 무작위는 덱 섞기에만 있다.
- ROOKIE 1명과 전투 4회, 중간 카드 보상 3회, 카드 12종. 시작 덱 10장, 최종 덱 10–13장.
- 평정심=플레이어 HP 50. 제구=상대 HP 34/44/54/70. 실제 야구 이닝/득점이 아닌 심리전의 전투 추상화다.
- 승리 시 HP 5 회복, 보상 3개 중 1장 또는 건너뛰어 추가 HP 4 회복. HP 0이면 패배, 마지막 전투를 이기면 클리어.
- 손패는 턴 종료 시 버리고 새로 5장. 뽑을 카드가 없으면 버린 카드를 섞는다. 소멸 카드는 다음 전투에 돌아온다. 뽑을 카드 목록은 순서를 숨긴다.
- 노림은 중첩당 다음 공격의 첫 타격 +3, 공격 시 전부 소비. 노림/유리한 카운트는 다음 턴에도 유지. 방어는 턴 시작에 초기화. 침착함은 이후 매 턴 방어 3.
- 투수의 의도는 공개된 고정 패턴이다. 현재 플레이어 선택을 몰래 보고 바뀌지 않는다. 직구 유도 카드만 현재 의도를 명시적으로 바꾼다.
- 첫 보상에서 직구 유도를 고르면 ‘볼 골라내기 → 직구 유도 → 풀스윙’ 연계 가능. 같은 손패에 모으는 덱 순환이 필요하다.
- 변화구에 풀스윙만 사용하면 피해 12. 위 3장 연계는 행동력 3으로 방어 5, 상대 공격 -2, 피해 25. 상대 방어/잔여 HP에 따라 실제 피해는 줄어든다.
