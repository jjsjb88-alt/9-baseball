# LAST LIGHT — 현행 설계와 인수인계

2026-09-09. 사용자의 제로베이스 재설계 요청에 따라 작성. 이전 NIGHT RUN(bf75910)과 CORE TEST는 보존용이며 현재 앱이 아니다.

## 1. 완주 가능한 게임

- ROOKIE 한도윤(목표 1점), ADAPTER 서이준(3점), FOX 차무영(4점)을 차례로 만난다.
- 매치당 3개의 공격 이닝, 즉 9아웃. 안타/볼넷으로 주자를 쌓고 홈으로 불러들인다. 단타는 1베이스, 2루타는 2베이스, 3루타는 3베이스씩 진루하는 단순화된 야구다. 병살·도루·희생타·상대 공격은 없다.
- 매치 종료 때 목표를 달성했으면 다음 상대, 미달이면 패배. 마지막 상대까지 달성하면 우승. 중간 실패를 점수 없이 통과시키지 않는다.
- 중간 이닝 2회×3매치 + 매치 사이 2회 = 완주 시 보상 8회. 숙련존 확장/접촉 향상/집중 회복 중 하나, 모든 존 숙련 후 첫 선택은 타구 질 향상으로 대체된다.
- 12번째 투구까지 타석이 끝나지 않으면 볼넷으로 처리한다. 무한 파울 방지를 위한 명시적 게임 규칙이다.

## 2. 한 공의 선택

1. READ: 공개 확률, 투수 리포트, 카운트, 지난 투구를 읽어 9존 중 하나를 고른다.
2. BET: 카드 0~1장을 선택한다. 기본 스윙은 카드 소비 없음. 추가 집중 베팅 0/1/2는 정확한 읽기에서 CQ/PQ를 올리지만 오독 시 더 큰 대가를 준다.
3. REVEAL: 플레이어가 선택하기 전에 생성된 실제 투구를 공개한다.
4. IMPACT: CQ로 접촉을 판정한 뒤 PQ로 타구 질을 판정한다. 정확한 읽기도 안타를 보장하지 않는다. 1.75초 연출 동안 재입력을 잠근다.

시작 숙련존은 중상/좌중/가운데/중하. 새 설계에서는 **존 카드가 아니라 타격 방식 카드**다. 숙련 코스와 카드 선택은 별개의 축이다. DRIVE/CONTACT/POWER/COVER/CUT 5종, 총 10장. 시작 및 이닝마다 손패 4장, 타석 종료 후 1장 보충, 뽑을 카드가 없으면 버림패를 섞는다.

PUBLIC은 일반 코스 확률이다. ROOKIE는 2스트라이크 중하, ADAPTER는 볼 다음 우상, FOX는 최근 노림 회피 + 2스트라이크 좌중이라는 성격을 갖는다. AI는 지난 선택만 보며 현재 카드/조준/집중 베팅은 보지 않는다. 데스크톱 PITCH LOG, 모바일 관찰 노트로 지난 투구를 확인한다.

## 3. 새 코드 구조

- `src/main.jsx`: 새 앱만 import.
- `src/reboot/data.js`: 투수/목표/카드/표시 문구.
- `src/reboot/engine.js`: 모든 상태 전이·시드 난수·확률·CQ/PQ·진루·저장 검증. 기존 게임 엔진 import 없음.
- `src/reboot/App.jsx`: UI·입력 잠금·연출 타이머·로컬 저장·일시정지. 확률 판정식 없음.
- `src/reboot/reboot.css`: 새 레이아웃/카드/연출/반응형. 저모션 설정 존중.
- `src/reboot/audio.js`: Web Audio 짧은 합성 효과. 기본 OFF, 사용자 조작으로 켜며 오디오 실패가 게임을 막지 않음.
- `src/reboot/policy.js`: 공개 정보만 전달하는 정책 인터페이스와 전체 런 시뮬레이션.
- `scripts/last-light-report.js`: 4정책 고정 시드 보고서. 기존 `test:policy`는 이전 게임 회귀 검사이며 새 게임 검증이 아니다.
- `assets/reboot/last-light-stadium.png`: 새로 생성한 프로젝트 자산. 생성 방식과 프롬프트는 같은 폴더 README.

상태 흐름: `brief → pitch → result → pitch / bench / finished`; `bench → pitch / brief`. 전이 함수는 허용된 phase가 아니면 원래 상태를 반환한다. UI ref와 엔진 phase가 중복 처리를 함께 막는다.

## 4. 저장과 재현

- 키 `9zone-lastlight-v1`. 이전 저장 키를 읽거나 덮어쓰지 않는다. 진행 중 새 런 교체는 확인 대화상자가 필요하다.
- 카드/주자/카운트/지난 투구/능력/난수 seed를 저장한다. 미공개 실제 존과 TRUE 분포는 JSON에서 제외한다.
- pending pitch는 `pitchSeed`와 공개 상태에서 동일하게 복원하므로 새로고침해도 다른 공을 다시 뽑지 않는다. 클라이언트 게임이므로 악의적인 저장 편집을 막는 보안 장치는 아니다.
- 손상된 배열·카드 구성·주자·판정 기록을 검사한다. 읽기 실패는 오류 표시 후 새 런 시작 가능. 쓰기 실패는 재시도 UI를 표시하고 성공 전에는 메뉴 이탈을 막는다.
- 1개 브라우저 저장 슬롯이며 클라우드 동기화가 아니다. 동시에 여러 탭에서 같은 런을 진행하는 동기화는 지원하지 않는다.
- 연출 중 새로고침하면 이미 저장된 결과 화면으로 복원한다. 연출 때문에 결과를 다시 계산하지 않는다.

## 5. 실행과 검증

```sh
npm install
npm run dev
npm test
npm run report:last-light
npm run build
```

설치된 패키지 관리자의 네트워크 메타데이터 조회가 막히면 기존 node_modules에서 직접 실행:

```sh
node node_modules/vitest/vitest.mjs run
node scripts/last-light-report.js 300
node node_modules/vite/bin/vite.js build
```

자동 테스트 41개: 신규 엔진 8개, 신규 UI 3개, 보존된 이전 버전 30개. 새 UI 완주 테스트는 시드 1118527에서 실제 카드/존 버튼을 클릭하여 154투구·72타석·3매치 우승·재도전을 확인하고, 첫 투구 후 메뉴 이탈/재마운트/이어하기를 확인한다. 판정 결과를 홈런으로 강제하는 테스트가 아니라 실제 새 엔진을 사용한다.

300개 시드, 각 `71237 + i×104729`, 이닝 보상은 첫 선택을 사용한 단순 정책 결과:

| 정책 | 완주 | 평균 투구(탈락 포함) | 완주 표본의 평균 투구 |
| --- | ---: | ---: | ---: |
| PUBLIC 우선 | 7.3% | 80.3 | 130.0 |
| 패턴 활용 | 18.0% | 93.6 | 133.4 |
| POWER 우선 | 7.3% | 88.9 | 126.7 |
| 지켜보기만 | 0% | 31.5 | 해당 없음 |

패턴 정책은 화면의 투수 힌트에 해당하는 조건에서 알려진 코스를 선택한다. 인간의 패턴 발견/학습을 시뮬레이션하지 않는다. 이 보고서는 지배전략과 종료 가능성을 검사하는 도구이며 재미의 증거가 아니다.

30분 가정: 완주 약 133구×판단+연출 평균 12초 + 브리핑/보상 약 3분 ≈ 30분. 빠른 입력이나 조기 탈락은 짧아진다. 대기 시간을 늘려 30분을 강제로 맞추지 않는다. 실제 사람 플레이 시간은 미측정이다.
