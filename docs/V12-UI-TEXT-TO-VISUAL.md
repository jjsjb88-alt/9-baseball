# V12 — 말로 설명하지 않는 화면 · UI/UX 그래픽 치환 기획안

> 근거: 2026-09-22 플레이테스트 피드백 + 사용자 방향 지시.
> **아직 구현하지 않았다.** 이 문서는 검수 대상이며, 검수·수정은 **아스트라**가 한다.

## 0. 이 기획안의 지시

사용자 지시 원문 요지:

> UI/UX를 최대한 직관적으로. **텍스트 최대한 줄이고.** 굳이 설명하지 않아도 되는 부분도 줄이고.
> **게임 방식은 변하지 않아도 된다.** 전체적으로 **그래픽이나 효과로 치환**하는 작업이 필요하다.

따라서 이 문서의 범위는 **표현 계층 단독**이다.

| 대상 | 비대상 |
| --- | --- |
| 화면에 뜨는 글자 · 라벨 · 문장 | 엔진 확률 · 피해 공식 · 카드 수치 |
| 정보를 전달하는 형태 · 색 · 움직임 | 카드 종류 · 스택 4장 · CONNECT 규칙 |
| 학습을 시키는 방법 | 난이도 · 밸런스 · 런 구조 |

**핵심 원칙 한 줄: 규칙은 그대로 두고, 규칙을 말로 하지 않는다.**

## 3. 설계 원칙 7개

1. **텍스트 예산.** 한 화면에 **문장은 1개 이하**, 텍스트 요소는 §9의 상한을 넘지 않는다.
2. **한 눈 원칙.** 내 선택이 만든 결과는 **한 곳에서** 보인다. 같은 값을 두 번 쓰지 않는다.
3. **정보 무손실.** 글자를 지우되 정보를 지우지 않는다. 지운 글자는 형태·색·움직임 중 **둘 이상**으로 되살린다.
4. **3채널 규칙.** 모든 상태는 `형태 + 색 + 움직임` 세 채널 중 **최소 두 개**로 표현한다.
   색 단독 금지(색각), 움직임 단독 금지(`prefers-reduced-motion`).
5. **야구 물체로 말한다.** 새 추상 위젯을 만들기 전에 **배트 · 공 · 존 · 투수 체력**으로 말할 수 있는지 먼저 본다.
6. **가르칠 때도 말하지 않는다.** 1회성 학습은 문장이 아니라 **데모 모션**이다.
7. **숫자는 감추되 버리지 않는다.** 상세 수치는 길게 누르면 열리는 선택 패널로 보존한다. 기본값은 닫힘.

### 3.1 접근성 예외 — 반드시 지킨다

- **`aria-label`의 텍스트는 줄이지 않는다.** 화면에서 지우는 것은 **시각 텍스트**뿐이다.
  스크린리더 경로는 오히려 보강한다(§11 축 8).
- `prefers-reduced-motion`에서는 움직임 채널을 끄되, **형태+색 정지 상태로 같은 정보가 읽혀야 한다.**
  움직임이 유일한 전달 수단인 표현은 이 기획에서 **불합격**이다.

## 4. 시각 언어 정의

이 게임이 표현해야 하는 개념은 결국 7개다. 각각 **하나의 물체**에 고정한다.

### 4.1 커버 = 켜진 칸 (기존 유지, 텍스트만 제거)

- 켜진 9존 칸 그 자체가 커버다. `COVER 5/9`라는 숫자는 **칸을 세면 나온다.**
- 처리: 숫자·라벨 삭제. 칸 발광 강도만 유지.
- 메인 카드 커버와 지원 카드 커버는 **테두리 두께**로 구분한다(메인 2px 실선, 지원 1px 점선).

### 4.2 위력 = 투수 HP 바 위의 **예상 피해 고스트** ★ 이 기획의 핵심

지금 세 군데에 흩어진 효율 표기를 **전부 삭제**하고, **투수 HP 바 하나**로 옮긴다.

```
투수 HP 바
[■■■■■■■■■■■■■■■■■■■□□□□□□□□]      ← 현재 HP (확정, 솔리드)
                 └ ▨▨▨▨ ┘                ← 이 스윙이 깎을 예상 피해 (반투명 + 사선 해치)
                        └ ⋰⋰ ┘           ← 정확 적중 시 추가분 (점선 테두리)
```

- 카드를 1장 더 놓으면 → **고스트 구간이 눈앞에서 짧아진다**(동시에 9존 켜진 칸은 늘어난다).
- 이어치기가 생기면 → **고스트 구간이 다시 조금 길어지고 끝단이 번쩍인다.**
- 플레이어가 배우는 문장: *"칸을 넓히면 덜 깎이고, 이으면 조금 돌아온다."* — **한 글자도 쓰지 않고.**

| 삭제되는 표기 | 개수 |
| --- | ---: |
| `PRESSURE 80% HP` + 보조문 | 3 |
| `HP POWER` / `HP ×0.80` / `FULL POWER` / `COVER +1 · 위력 -20%` | 4 |
| 1~4장 배율 스트립(`1장 ×1.00 FULL` …) | 12 |
| `BASE` `+` `CONNECT` `=` `FINAL` 4칸 | 8 |
| `PRECISION MAIN` + `정확 적중 ×1.5` + 보조문 | 3 |
| **합계** | **30** |

→ 대체물: **HP 바 1개.** 숫자 0개.

### 4.3 이어치기 = 배트 궤적 아크 (CONNECT / BREAK)

- 현행: 선 + `CONNECTED` / `BREAK` 텍스트 칩 + `1 → 2` + 존 이름.
- 대체: **하나의 연속 배트 궤적**을 9존 위에 그린다.
  - 이어짐: 끊김 없는 **발광 아크**, 굵기 일정, 진행 방향으로 흐르는 미세 스윕.
  - 끊김: 아크가 **물리적으로 끊긴 틈** + 끝단 파편 2~3px + 색 탈채도. 틈은 정지 화면에서도 보인다(형태 채널).
- 순서 변경 미리보기(`← 앞 +1`, `뒤 → -1`)의 숫자 삭제 → **아크가 실시간으로 다시 그려지고**,
  동시에 §4.2 고스트 구간이 움직인다. 결과를 숫자로 예고하지 않고 **결과 자체를 미리 보여준다.**

### 4.4 순서 = 토큰 ①②③④ (유지)

- 숫자 기호는 언어가 아니다. **유지한다.**
- 삭제: `SWING ORDER`, `DRAG`, `≡ 손잡이로 끌거나 버튼으로 이동 · 같은 존·8방향 인접 = CONNECT`,
  `MAIN SWING` / `SUPPORT` 이름표, 존 이름 부제.
- 유지: `≡` 핸들 **모양**(글자 `DRAG` 없이), 토큰 번호, 앞/뒤 이동 **화살표 아이콘**.

### 4.5 카드 = 3×3 글리프 + 아이콘 1줄

현행 카드 1장의 텍스트 행: `준비/스윙` · `역할 · 축` · 이름 · `gives/needs` 칩 · 규칙문 ·
강화문 · 연계/상충문 · 노트 · 푸터 = **최대 9행**.

| 유지 | 대체 | 삭제(상세로 이동) |
| --- | --- | --- |
| 카드 이름 | 커버 3×3 글리프(기존 `CoverageMini` 확대) | 규칙 설명문 |
| 역할 아이콘 1개 | `gives/needs` → 아이콘 칩 | 강화 설명문 |
| | 연계/상충 → 카드 테두리 색+모양(연계 실선 발광 / 상충 빗금) | 푸터 플레이버 |

- **길게 누르기 = 상세 패널**(원문 텍스트 전부 보존). 기본은 닫힘.
- 카드 1장 텍스트 행 **9 → 1**(이름만).

### 4.6 투수 읽기 = 9존 히트 셰이딩 (텍스트 제거)

- 현행: `코스 경향 · 확정 예고 아님` 같은 문장 + `READ` 라벨 + 등급 설명.
- 대체: 9존 칸의 **명암 + 해치 패턴**(등급 0=거친 해치, 등급 2=중간, 등급 4=정밀). 색 단독 금지.
- 투수가 **안 던지는 존**은 칸을 **비활성 질감**(눌린 회색 + 격자)으로. "확률 0"이라고 쓰지 않는다.
- `information.js`의 등급 계약은 **그대로**다. 표기만 바꾼다.

### 4.7 카운트 · 아웃 · 주자 = 전광판 (현행 유지)

야구 관습 기호이므로 손대지 않는다. 이 기획에서 **비대상**.

## 6. 무언(無言) 온보딩 — 문장 대신 데모

§2.4의 결론은 "투어를 켜라"가 아니다. **투어는 텍스트 6장이다. 이번 방향과 정반대다.**

### 6.1 대체안 — 고스트 데모

첫 런 첫 타석에서, 화면이 **스스로 한 번 해 보인다.**

| 구간 | 길이 | 화면에서 벌어지는 일 | 텍스트 |
| --- | ---: | --- | --- |
| 1 | 0.6s | 9존 한 칸이 **펄스** → 반투명 고스트 손가락이 그 칸을 탭 | 0 |
| 2 | 0.7s | 손패 카드 1장이 **떠올라** 그 칸으로 날아가 앉음 → 커버 칸 점등 | 0 |
| 3 | 0.5s | 투수 HP 바에 **고스트 피해 구간**이 차오름 | 0 |
| 4 | — | 고스트 손이 사라지고 **실제 손패가 같은 동작을 기다린다**(해당 칸만 펄스 유지) | 0 |

- 플레이어가 **따라 하면 끝난다.** 스킵은 아무 곳이나 탭.
- 2번째 타석 이후 재생하지 않는다. 기존 저장은 완료로 간주한다.
- **첫 공 결과를 조작하지 않는다.**(이전 초안의 "첫 공 안타 보장"은 폐기. 밸런스 비대상 원칙 위반이었고,
  데모는 *조작 방법*을 가르치지 *결과*를 가르치지 않는다.)

### 6.2 개념별 1회 데모

겹쳐치기·순서 변경도 같은 방식으로, **그 기능을 처음 쓸 수 있게 된 순간 1회만** 0.8s 데모.
`b.turn<=2` 시간 게이트를 **개념별 1회 플래그**로 교체한다(§2.5 해결).

| 개념 | 데모 | 트리거 |
| --- | --- | --- |
| 겹쳐치기 | 2번째 카드가 얹히며 고스트 구간이 **줄어드는** 것을 보여줌 | 손패에 지원 가능 카드 2장 이상이 처음 생긴 타석 |
| 이어치기 | 아크가 **끊김 → 이어짐**으로 바뀌며 고스트가 **늘어남** | CONNECT가 가능한 배치가 처음 나온 순간 |
| 순서 변경 | 토큰 2개가 자리를 바꾸며 아크가 재구성됨 | 지원 2장 이상이 처음 배치된 순간 |

각 데모는 **문장 0개**다. 보여주는 것이 설명이다.
