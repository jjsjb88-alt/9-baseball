### 3.3 간격·조작 영역

간격 4/8/12/16/24/32px, 반경 2/8/pill을 기본으로 한다.
조작 영역은 최소 44×44 CSS px, 존은 가급적 48×48 이상이다.
눈에 보이는 카드 모양과 실제 조작 영역을 분리하고 이웃 타겟을 침범하지 않는다.

### 3.4 z-index

field 0 / actors 10 / vfx 20 / board 30 / hud 40 / drawer 50 / overlay 60 / modal 70.
명명된 토큰으로 관리하되 실제 stacking context와 pointer hit testing을 확인한다.
숫자가 크다고 다른 stacking context 위로 올라간다고 가정하지 않는다.

### 3.5 모션

UI 완료 시간: tap 120ms / state 180ms / move 260ms / reveal 420ms.
시각 반응 **시작 ≤100ms**와 애니메이션 완료 시간을 구별한다.
이징: standard cubic-bezier(.2,.8,.2,1), accel (.4,0,1,1), decel (0,0,.2,1).
기존 presentation.js 결과 타임라인·V4 60Hz·reduced-motion 60ms·성능 예산은 변경 대상이 아니다.

### 3.6 반응형

compact ≤430px, short=가로이면서 높이 ≤430px, regular ≥700px, wide ≥1100px를 설계 분기점으로 한다.
CSS custom property를 media query 조건에 직접 넣는 구현을 전제하지 않는다.
중간 폭·safe area·브라우저 바·200% 확대를 확인한다.
overflow:hidden으로 넘친 행동 버튼을 감춰 맞췄다고 판정하지 않는다.

### 3.7 CSS 이관 — 일괄 래핑 금지

P0는 기준 캡처·토큰·신규 코드 감시부터 한다. 기존 파일 전체를 여러 레이어로 감싸지 않는다.
일반 선언은 뒤 레이어가 우선이고 레이어 밖 일반 선언이 우선한다.
**!important는 앞 레이어가 우선하며 레이어 안 important가 레이어 밖 important보다 우선한다.**
따라서 2266개의 important가 있는 코드를 래핑만 해도 우선순위가 역전될 수 있다.
레이어 미지원 브라우저에서는 내부 규칙이 무시될 수 있으며 '자동 폴백으로 안전'하지 않다.
근거: [MDN @layer](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@layer).

컴포넌트별 import 순서·경쟁 selector·일반/important·미레이어 규칙을 기록하고 작은 단위로 이관한다.
!important 1200/300 같은 임의 총량은 합격 조건에서 제외한다.
변경 화면과 공유 selector의 다른 화면을 캡처 비교하고, 차이가 없거나 의도한 차이임을 설명한다.

## 4. 화면 배치

### 4.1 상태별 초점

읽기=공개 분포/투수, 설계=보드/손패/효율, 판정=공/배우/실제 결과.
다른 영역을 일괄 opacity .45로 흐리면서 상호작용은 유지하지 않는다.
조작 가능한 라벨·버튼의 대비와 포커스는 항상 유지한다.

### 4.2 세로

390×844에서 전광판, 경기장, HP/효율, 보드, 손패, **실행 버튼**까지 실제 상태로 검증한다.
기존 시안은 높이 844 고정·overflow:hidden을 사용하므로 반응형 합격 증거가 아니다.
실행 버튼이나 긴 이름이 잘리면 경기장 높이·공간 배분·스크롤을 조정한다.

### 4.3 가로/PC

844×390은 좌 경기장/우 조작판을 후보로 검증하고 손패와 확정 버튼의 접근을 우선한다.
1440×900은 같은 정보를 넓게 배치하되 모바일 단순 확대판으로 만들지 않는다.
지도·모달·보상·시설의 스크롤과 회전 후 포커스를 함께 검사한다.

## 7. 입력 계약

### 7.1 스크롤과 드래그

8px에서 드래그를 먼저 잡고 12px에서 스와이프를 판정하면 손패 스크롤을 가로챈다.
카드 전체는 native 손패/문서 스크롤을 우선한다. 전용 드래그 핸들에서만 pointer capture와
touch-action:none을 허용하는 기존 패턴을 우선 유지한다.
세부 임계값은 실기기로 검증한다. 200~399ms 입력이 아무 동작도 하지 않는 공백을 만들지 않는다.

탭→존 탭과 키보드가 모든 배치를 수행해야 한다.
pointercancel·회전·보드 밖 드롭·capture 해제 시 임시 상태를 복구하고 게임 상태를 바꾸지 않는다.
길게 누르기는 상세의 보조 경로이며 스크롤이나 명시적 상세 버튼을 대체하지 않는다.

### 7.2 확정·회수

기존 확정 한 번으로 실행한다. 추가 무장→확정 2단계는 넣지 않는다.
편집 토큰을 눌렀다고 삭제하지 않는다. 명시적 회수·순서 버튼으로 의도를 구분한다.
이미 확정된 행동은 중복 실행되지 않으며 취소는 기존 상태 계약을 따른다.

### 7.3 피드백

시각 반응은 필수다. 소리·햅틱 실패나 미지원이 실행을 막지 않는다.
무효 입력·불가 조건은 흔들림만으로 끝내지 않고 짧은 이유를 접근 가능하게 제공한다.
스윙 확정 뒤 기존 연출에 넘기고 새로운 지연을 누적하지 않는다.

### 7.4 경계 상태

BASIC, 빈 손패, 지원 4장 초과, 번트, 주자 없음, 준비 소진, 같은 존 중복,
손패 스크롤 끝, 기존 저장 복원, 모달 열린 상태, reduced-motion을 확인한다.
상태별 오류와 복구 경로는 텍스트 예산의 예외다.

## 8. 모션

배치·회수·순서 변경의 출발점은 추적 가능하게 한다.
여러 셀 스태거는 장식일 뿐, 실제 선택/커버 상태를 늦게 적용하지 않는다.
reduced-motion에서는 이동·스태거 대신 즉시 최종 상태와 정적 연결/끊김을 표시한다.
데모는 짧은 정지 설명과 재생/건너뛰기를 제공한다.

## 9. 텍스트

중복 장식 문구부터 줄인다. 손패 이름·조건·비용·오류를 남긴다.
긴 이름을 글자 크기 축소로 해결하지 않는다. 영어 장식 헤더는 제거 후보이나
B/S/O도 초보에게 설명 없이 자명하다고 가정하지 않고 도움말을 제공한다.
같은 값은 같은 맥락에 중복하지 않되 작은 화면의 필요한 고정 요약까지 금지하지 않는다.

## 10. 삭제와 테스트의 순서

삭제할 문구마다 **현재 의미 → 대체 시각/상세 → 접근 가능한 이름 → 검증**을 기록한다.
기존 9개 테스트 파일 33곳이라는 원 감사 수치는 구현 시 다시 확인한다.
역할·이름·상태·실제 소비/이동을 검증하는 테스트를 data-* 존재 확인으로 약화하지 않는다.
문구만 바뀌면 같은 기능 검증을 보존하며 selector를 갱신한다.

## 11. 온보딩/저장

UI 설정은 신규·기존 사용자·스킵·재생·저장 실패를 구분한다.
결측을 모두 '이미 봄'으로 해석하면 신규 사용자도 도움을 받지 못한다.
게임 세이브에 onboarding을 임의 추가하거나 스키마 버전 유지가 안전하다고 단정하지 않는다.
기존/손상 저장 복구와 round-trip을 검증하고 도움말은 언제든 열 수 있게 한다.

## 17. 기존 시안의 사용 범위

[시안 입구](./design/v12/README.md)에서 A/B/C와 카드 형태 PNG/HTML을 본다.
시안은 **정적 구성 비교 자료**다. 엔진/드래그/반응형/모션 증거가 아니며 고정 390×844를 벗어나면 검증되지 않았다.
카드 접촉=연결, 불투명 커버, 확정 HP처럼 보이는 고스트는 폐기된 개념이다.
PNG에 남은 '직관적'·별점·구현 난도는 작성자의 설계 판단이며 사람 실험 결과가 아니다.

## 부록. 정적 재측정 방법

src/duel/*.css를 UTF-8로 읽고 다음을 별도 집계한다.
파일 수·개행 수, !important 등장 횟수와 포함 줄 수,
hex/rgb/rgba 리터럴 등장 횟수와 소문자 중복 제거 문자열 수,
