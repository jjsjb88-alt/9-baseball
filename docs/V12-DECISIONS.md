## D1. 전투 화면 시각 방향 ★ 최우선

`design/v12/three-directions.png`

- [ ] **A · 타자 시점** — 9존이 경기장 공간 안. HP는 마운드 위 빛의 고리
- [ ] **B · 전광판** — 화면 전체가 야구 전광판. 읽기 등급 = 전구 밝기
- [ ] **C · 덱 테이블** — 상대 위 · 슬롯 보드 중앙 · 큰 카드 아래
- [ ] 혼합 (어떻게: ____________)

| | A | B | C |
| --- | :-: | :-: | :-: |
| 야구 정체성 | ★★★ | ★★ | ★ |
| 초보 즉시 이해 | ★★ | ★★★ | ★★ |
| 덱빌딩 관습 | ★ | ★ | ★★★ |
| 9칸 좌표 비교 | ★ | ★★★ | ★★★ |
| 아트 의존도 | 높음 | 낮음 | 중간 |
| 구현 난도 | 상 | 하 | 중 |

**파급**: 전 화면 레이아웃 + 아트 일정. A를 고르면 **아트 리부트가 선행 조건**이 된다.
**의견 없음**을 골라도 된다. 그 경우 B로 프로토타입을 먼저 만들어 A/C와 비교하는 것을 권한다(가장 싸다).

## D2. 카드가 존을 **물리적으로 덮는가** ★ 기획의 척추

`design/v12/card-shape-language.png` 하단 보드 데모.

- [ ] **덮는다** — 카드 형태 = 커버 범위. 카드가 칸을 가린다
- [ ] **테두리만 밝힌다** — 현행처럼 토큰만 놓고 칸 테두리로 표시
- [ ] 보류 — 실물 프로토타입을 본 뒤 결정

**파급**: "덮는다"가 부정되면 `COVER n/9` 표기가 다시 필요해지고 §4(보드) 전체가 재설계된다.
**알려진 위험**: 390px에서 십자 카드는 판의 절반을 가린다. 미검증이다.
