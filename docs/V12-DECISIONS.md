## D2. 카드가 칸을 덮는 방식

- [x] **반투명 커버·테두리 + 순번 토큰 + 순서 링크**
- [ ] 사용자 확정

불투명 카드로 분포·좌표·순번을 가리는 안은 채택하지 않는다.
coverageAt으로 계산한 셀을 표시하고 stackPlan.links로 연결을 그린다.
카드 접촉이나 커버 겹침은 연결 조건이 아니다.
COVER 숫자의 시각적 생략은 작은 화면에서 실제 커버 식별을 검증한 뒤 결정한다.

## D3. 카드 이름 재명명

- [x] **현재 16종 이름 유지**
- [ ] 사용자 확정

이름 길이 통일은 규칙 이해 문제를 해결하지 않는다.
긴 이름은 줄바꿈·상세·선택 상태의 공간 배분으로 처리한다.

## D4. 전투의 카드 이름

- [x] **손패에서 유지**, 12px 이상. 선택/상세는 더 크게 표시
- [ ] 사용자 확정

자동으로 이름을 감추지 않는다. 보드는 순번과 선택 시 이름, 상세는 원문 규칙·조건을 제공한다.
길게 누르기 외에 명시적 정보 버튼과 키보드 경로도 유지한다.

## D5. 준비 카드의 원형 실루엣

- [x] **원형 실루엣을 비교 프로토타입에 사용하되 이름·일정한 조작 영역 유지**
- [ ] 사용자 확정

둥글기만 하면 조작을 안다는 가설은 기각한다.
준비 잔여 횟수·발동 버튼·사용 불가 이유가 필요하다.
모양에 맞춘 불규칙 hit area와 '존으로 끌면 튕김' 중심 학습은 채택하지 않는다.

## D6. 단계별 배포

- [x] **별도 통합 프리뷰에서 검증하고, 서로 의존하는 P1~P4는 함께 제품 검수**
- [ ] 사용자 확정

P0는 화면 변화 없는 기반 작업으로 독립 검토한다.
후속 화면도 코드 단위는 작게 나누되 이름·규칙·접근성이 중간 단계에서 사라지면 공개하지 않는다.
현재 PR의 문서 갱신은 main 병합이나 공개 배포 승인이 아니다.

## D7. 아트 리부트와 순서

- [x] **파일 소유권을 나눠 UI 검증과 아트 작업을 병행할 수 있는 구조**
- [ ] 사용자 확정

이는 병렬 에이전트 실행 지시가 아니라 작업 경계 권고다.
아트의 배우·60Hz·경기장 계약과 UI의 보드·손패·상세를 분리한다.
App.jsx·공유 CSS 변경은 기준 브랜치와 통합 순서를 먼저 정한다.
UI 시안으로 아트 품질을 합격 처리하지 않는다.
