# 9ZONE SHOWDOWN — 화면 설계서 v1

> 대상: 모바일 세로(360×800 기준), 한 손 조작
> 목적: 알파 피드백 "뭘 하는지 모르겠음 / 뭐가 진행되는지 알 수 없음" 해결
> 이 문서는 코덱스·클로드코드에 그대로 던질 수 있는 구현 명세다.

---

## 0. 진단과 원칙

### 문제의 정체

"뭘 하는지 모르겠음"은 **설명 부족이 아니다.** 튜토리얼을 더 쓰면 더 안 읽는다.
상태–행동–결과 루프가 화면에 안 보이는 것이 원인이다.

매 순간 화면이 아래 셋에 답해야 한다.

| # | 질문 | 담당 |
|---|---|---|
| 1 | 지금 누구 차례고 뭘 기다리는가 | 페이즈 라벨 + 활성 영역 |
| 2 | 내가 이걸 누르면 뭐가 되는가 | 확정 전 미리보기 |
| 3 | 방금 왜 그 결과가 나왔는가 | 인과 3줄 결과 배너 |

### 최상위 원칙

> **한 페이즈에 한 질문. 활성 영역은 항상 하나.**

한 화면에 전부 띄우지 않는다. 정보량은 유지하되, 단계마다 **하나만 활성 / 나머지는 흐리게(dim)**.
정보를 지우는 게 아니라 **주의를 좁힌다.**

## 1. 상시 레이아웃과 시각 위계

```
┌──────────────────────────────┐
│ ① 투수 HP 바         62/100  │  56dp  상단 고정
├──────────────────────────────┤
│ ② 투수 카드 / 페이즈 라벨    │  72dp
│    THE ROOKIE                │
│    ▸ 코스를 예측하세요       │
├──────────────────────────────┤
│ ③ 히스토리 스트립            │  64dp
│    [전체][이 카운트][주자]   │
│    ◆ ◇ ◆ ◆ ◇ ◆             │
├──────────────────────────────┤
│                              │
│ ④ 9존 그리드                 │  240dp
│    (thumb zone)              │  정사각
│                              │
├──────────────────────────────┤
│ ⑤ 카운트 · 아웃 · 집중       │  48dp
│    B ●○○○  S ●●○  OUT ●○○   │
├──────────────────────────────┤
│ ⑥ 액션 바 / COMMIT 버튼      │  88dp  하단 고정
└──────────────────────────────┘
```

### 위계 규칙 (게이지 2개 충돌 방지)

| 지표 | 위치 | 형태 | 색 | 성격 |
|---|---|---|---|---|
| 투수 HP | 최상단 고정 | 가로 바 | 단색 채움 | **목표까지 거리** |
| 볼카운트·아웃 | 그리드 바로 아래 | 점(dot) | 무채색+포인트 | **남은 시간** |

- HP는 **바**, 카운트는 **점**. 형태 자체를 다르게 해서 혼동 차단
- HP 바는 감소할 때만 0.4초 애니메이션 + 숫자 팝업. 평소엔 조용히 있는다
- 카운트는 변할 때 해당 점만 깜빡. 전체 강조 금지

### 페이즈 라벨 — 질문 1의 답

②의 두 번째 줄은 **항상 지금 할 일을 명령형 한 줄**로 말한다.

```
OBSERVE  ▸ 투수를 관찰하세요        (자동 진행, 탭하면 스킵)
READ     ▸ 코스를 예측하세요
BET      ▸ 확인 후 승부하세요
REVEAL   ▸ (라벨 숨김)
동료타석 ▸ 3번 타자 진행 중…       ← 이거 없어서 "진행을 모르겠다"가 나옴
```

동료 타석 자동 진행 중에도 반드시 라벨을 띄운다. **빈 화면에 아무 설명 없이 뭔가 돌아가는 상태를 만들지 않는다.**

## 2. 페이즈별 화면

### PHASE 1 — OBSERVE

목적: 카드를 보기 전에 **투수부터 보게** 만든다.

| 요소 | 상태 |
|---|---|
| 히스토리 스트립 | **활성** (필터 탭 가능) |
| 9존 그리드 | dim 40%, 입력 차단 |
| 액션 바 | dim, 비활성 |
| 확률 오버레이 | 표시 |

- 투수 와인드업 준비 모션 재생
- 아무 곳이나 탭하면 즉시 READ로 (숙련자 스킵)
- 최대 대기 2.5초 후 자동 전환

**여기서 그리드를 잠그는 게 핵심.** 열려 있으면 플레이어는 히스토리를 안 보고 바로 확률 최고 존을 누른다. 그게 지금까지의 지배전략이었다.

---

### PHASE 2 — READ

목적: 코스 예측. 폭 지정.

| 요소 | 상태 |
|---|---|
| 9존 그리드 | **활성** |
| 확률 오버레이 | 20% 불투명도로 낮춤 |
| 히스토리 | 그대로 표시(읽기 전용) |
| 액션 바 | dim |

#### 스와이프 입력

```
드래그 시작 → 지나간 칸 하이라이트 (연속 영역만)
불연속 칸 진입 → 무시 + 짧은 진동
손 떼기 → 폭 확정 → BET로 전환
```

- 최소 1칸, 최대 = 캐릭터 폭 상한(초기 4)
- 상한 초과 시 더 안 늘어남 + 상한 배지 깜빡
- **드래그 중 실시간으로 폭 숫자 표시** (그리드 우상단 `2칸`)
- 잘못 잡았으면 그리드 밖으로 드래그해서 취소

#### 오조작 방지

- 칸 히트박스는 시각 칸보다 상하좌우 4dp 넓게
- 80dp 이상 정사각 칸 유지 (240dp / 3 = 80dp)
- 손가락 아래 가려지는 칸은 그리드 상단에 **미니 미러**로 복제 표시

---

### PHASE 3 — BET  ← 피드백 직격 해결 지점

목적: **확정 전에 결과를 미리 보여준다.** 질문 2의 답.

```
┌──────────────────────────────┐
│  선택   중단 · 우하  2칸      │
│                              │
│  적중 예상    58%             │
│  데미지 배율  ×1.4            │
│  약점 존 포함  ⚠ 우하 0.7     │
│                              │
│  [POWER 집중2] [CUT 1] [FOCUS 2]│
│                              │
│  ┌────────┐   ┌──────────┐   │
│  │  취소  │   │  승부!   │   │
│  └────────┘   └──────────┘   │
└──────────────────────────────┘
```

- 그리드 위로 올라오는 **바텀시트**. 그리드 선택 영역은 계속 보이게(시트 높이 45% 이하)
- 액션 버튼을 누르면 **미리보기 숫자가 즉시 갱신**된다 (POWER 누르면 적중률 내려가고 배율 올라감)
- 집중 부족하면 버튼 회색 + 필요량 표시. 숨기지 않는다
- `승부!` 눌러야 투구. **이게 김민기가 말한 "설정한 걸 진행하겠냐고 안내"**

#### 미리보기 숫자 규칙

| 표시 | 근거 | 정직성 |
|---|---|---|
| 적중 예상 % | PUBLIC 분포에서 선택 영역 합 | 정직. 조건부는 안 알려줌 |
| 데미지 배율 | 폭 배율 × 존 배율 (확정값) | 완전 정직 |
| 약점 경고 | 존 배율 0.9 미만 포함 시 | 완전 정직 |

**READ 등급(DEEP READ 여부)은 미리 안 보여준다.** 보여주면 정답을 알려주는 것.

---

### PHASE 4 — REVEAL

목적: 인과를 보여준다. 질문 3의 답.

```
확률 오버레이 사라짐  →  히스토리 사라짐  →  그리드만 남음
        ↓
    와인드업 (0.6초)
        ↓
    공 궤적 (0.5초)
        ↓
    착탄 칸 플래시
        ↓
  ── 판독 결과 먼저 ──
    READ 배너 (0.25초 히트스톱)
        ↓
    스윙 / 타구
        ↓
    결과 배너
```

**순서 엄수.** 판정 결과가 타격보다 먼저 뜬다.
`홈런 → 잘했네`가 아니라 `내 판단 적중 → 그래서 홈런`.

#### 결과 배너 — 인과 3줄 고정 포맷

```
    READ 성공
    좋은 타구
    안타 · 투수 HP −16
```

```
    READ 성공
    빗맞음
    뜬공 아웃 · HP −0
```

```
    빗나감  (실제: 우하)
    헛스윙
    스트라이크
```

- 1줄 = 판독 / 2줄 = 실행 / 3줄 = 야구 결과 + HP
- **1·2줄 분리가 절대 원칙.** 이게 없으면 "잘 읽었는데 못 쳤다"가 플레이어에게 존재하지 않는다
- 오독 시 `WRONG!` 대형 표시 금지. 공이 반대편에 꽂히는 것 자체가 연출. 괄호로 실제 위치만 조용히 표기
- 배너 유지 1.2초, 탭하면 즉시 스킵

## 3. 첫 투구 가이드 — 텍스트 0줄

기존 튜토리얼 슬라이드 **전량 폐기.** 아무도 안 읽는다.

첫 경기 첫 투구를 **강제 가이드 시퀀스**로:

```
1. 화면 전체 어둡게, 히스토리만 스포트라이트
   손가락 아이콘이 [이 카운트] 필터를 탭
   (0.8초)

2. 스포트라이트 그리드로 이동
   손가락이 2칸 스와이프 시연 → 하이라이트 남음
   (1.2초)

3. BET 시트 자동 등장, 숫자에 링 강조
   손가락이 [승부!] 탭
   (1.0초)

4. 투구 → READ 배너 → 결과 배너 풀 재생
   (2.5초)

5. "이제 직접 해보세요" — 유일한 텍스트 1줄
```

- 총 6초 이내
- 언제든 탭으로 스킵 가능, 스킵해도 다시 안 뜸
- 2번째 투구부터 완전 자유

### 문맥 힌트 (튜토리얼 대체)

새 요소가 처음 등장할 때만 해당 UI 옆에 짧은 말풍선 1개.

| 트리거 | 문구 |
|---|---|
| 집중 최초 획득 | `집중으로 POWER를 쓸 수 있어요` |
| 폭 1칸 최초 선택 | `좁을수록 데미지가 큽니다` |
| DEEP READ 최초 | `투수 습관을 읽었습니다` |
| HP 50% 도달 | `투수가 흔들립니다` |

각 1회만. 누적 4개 이하. 설정에서 끌 수 있음.

## 4. 안티패턴 (금지 목록)

- 두 영역이 동시에 활성 상태로 입력 대기
- 확정 없이 탭 즉시 투구
- 결과를 `안타!` 한 단어로만 표시
- 동료 타석/자동 진행 중 라벨 없는 화면
- 튜토리얼 텍스트 3줄 초과
- HP와 볼카운트를 같은 형태(둘 다 바 / 둘 다 점)로 표시
- 미리보기에 READ 등급 노출
- 모달 팝업으로 흐름 끊기 (바텀시트만 사용)

## 5. 구현 체크리스트

- [ ] 페이즈 상태머신 단일 소스 (`phase: OBSERVE|READ|BET|REVEAL|AUTO`)
- [ ] 각 페이즈마다 입력 허용 영역이 **정확히 하나**임을 코드로 보장
- [ ] 페이즈 라벨이 모든 상태에서 비어 있지 않음 (동료 타석 포함)
- [ ] 스와이프 연속성 검증 (불연속 칸 거부 + 햅틱)
- [ ] 폭 상한이 캐릭터 스탯에서 읽힘 (하드코딩 금지)
- [ ] BET 시트 미리보기가 액션 토글에 실시간 반응
- [ ] 미리보기 계산이 실제 판정 엔진(`resolvePitch`)과 **같은 함수** 사용 — 별도 근사식 금지
- [ ] 결과 배너 3줄이 판독/실행/결과로 분리 렌더
- [ ] HP 감소 애니메이션과 카운트 변화가 시각적으로 구분됨
- [ ] 첫 투구 가이드 1회 재생 후 플래그 저장
- [ ] 내 타석 TURN GUARD 회귀 없음

## 6. 수용 기준 (테스터 재검증)

이전 피드백이 해소됐는지 판정하는 기준.

- [ ] 설명 없이 켠 테스터가 **첫 투구를 스스로 완료**한다
- [ ] "지금 뭘 해야 하냐"는 질문이 나오지 않는다
- [ ] 결과를 보고 **"내가 왜 이렇게 됐는지"를 말로 설명**할 수 있다
- [ ] 폭을 상황에 따라 바꾼다 (매번 같은 폭 아님)
- [ ] HP 바를 보고 "이 투수 거의 다 잡았다"고 말한다
- [ ] 오조작으로 의도치 않은 투구가 발생하지 않는다

3개 이상 미달이면 시스템 추가 중단, 화면 재설계.

---

## 7. 미해결

1. 히스토리 조건 필터를 첫 경기부터 열지, MIND 성장으로 해금할지 — 초반 인지부하와 트레이드오프
2. 손가락 가림 대응: 미니 미러 vs 그리드를 화면 상단 배치
3. 가로 모드 지원 여부
4. REVEAL 총 4.4초가 20~30구 반복 시 길지 않은지 — 2회차부터 단축 재생 검토
