# V13 BALLPARK — 방향 확정 · 2026-09-25

이름: 처음엔 "야간경기(NIGHT GAME)"였다. 경기장을 밝게 쓰기로 하면서(규칙 2) "볼파크"로 바꿨다 — 경기장이 곧 화면이라는 뜻. 코드 이름 `BallparkBattle`, `ballpark.css`(`.bp-*`), 플래그 `?park=1`(옛 `?park=1`·`9zone-ng`도 받아 옮긴다).

시안: https://claude.ai/artifact/89BnSGR6YvrU47Nr3u8YVz (소스 `ballpark-mock.tpl.html`, 캡처 `mock-*.png`).
사용자 판정: "이 방향 좋아" → "좋아 이 느낌으로 가자" (2026-09-25).

## 왜 바꾸나

- 픽셀 조정(12px 하한, 겹침 수정)으로는 "별로"가 해결되지 않았다. 문제는 디자인 방향이었다.
- 전투 화면에 박스 9개와 설명문 12줄이 경기장 그림을 덮는다. 강조색이 없고, 그림체(SD 캐릭터 · 칠한 경기장 · 웹 패널)가 서로 다른 게임처럼 보인다.
- 문구가 규칙 설명서처럼 길고 현학적이다.
- 기준: 아르티스 임팩트처럼 장면 하나가 화면이 되는 도트 게임.

## 여섯 가지 규칙 (모든 화면)

1. **장면이 먼저.** 위아래 검은 띠 안에 경기장 한 장면. 정보 패널은 장면 위에 올리지 않고 띠로 내린다.
2. **경기장은 밝게** (사용자 2026-09-25: "캐릭터가 밝은 건 밝은 경기장을 쓰면 되지"). 밝은 SD 캐릭터를 어둡게 누르지 않고, 경기장 원본 밝기를 쓴다. 장면 위 글자는 먹색 받침(`#07080dcc`) 위에 둔다. 어두운 건 위아래 띠뿐.
3. **강조색은 하나.** 조명 노랑 `#ffc861`만. 노리는 칸, 휘두르기 버튼, 볼카운트 불빛, 갈 수 있는 지도 칸. 나머지는 남색 `#141a33` · 먹색 `#07080d` · 뼈색 `#ece4cf` · 청회색 `#7b84a6`.
4. **UI는 그림 속에.** 9존은 중계 화면처럼 타석 앞에 뜬 스트라이크 존. 투수 HP는 머리 위 눈금 12칸. 볼카운트는 구석의 작은 불빛.
5. **행동은 동사 두 개.** "휘두른다" / "지켜본다". 효율·커버 계산은 버튼 아래 한 줄. 원문 규칙은 카드 상세 시트.
6. **설명하지 말고 말하기.** 짧은 해설자 톤. 불확실함은 "확정 예고 아님" 같은 단서 대신 속삭이는 글씨체(기울임)로.

글꼴: 제목 Black Han Sans, 본문 Gowun Dodum, 숫자·라벨 Silkscreen.

## 지도

투수는 검은 실루엣, 갈 수 있는 곳만 노랗게 빛난다. 시설은 7×7 도트 아이콘. 누르면 아래(휴대폰) / 오른쪽(PC)에 컬러 초상화 · 한 줄 성격 · HP 눈금 · 보상 한 줄. 2·3막은 한 줄 예고.

## 미정

- 말투: 해설자 톤(시안) vs 코치 반말 톤.
- ~~캐릭터 밝기~~ → 밝은 경기장으로 해결(규칙 2).

## BP-1 기록 · 2026-09-25

- `src/duel/BallparkBattle.jsx`, `ballpark.css`(모두 `.bp-*`), `ballpark-copy.js`. App은 `?park=1`(기억됨, `?ng=0`으로 끔)일 때 `phase==='battle'`·연출 없음에서만 새 화면을 그린다. 투구 연출·결과는 옛 화면.
- 입력: 카드 → 칸 = 메인(엔진 `setAimZone`), 메인이 있을 때 다른 카드 → 칸 = 지원(②③④, `swingStack`), 메인 다시 누르면 비움. 준비 카드는 원형 토큰, 버튼이 "준비한다"로 바뀜.
- 9존 칸 밝기 = 투수가 던질 몫(`publicProbabilities`), 던지지 않는 코스는 빗금.
- 글꼴은 `index.html`의 Google Fonts 링크(전역 로드, 쓰는 곳은 `.bp-battle`만). 이 컨테이너는 외부 글꼴이 막혀 캡처에는 대체 글꼴이 보인다.
- 검증: `tests/ballpark-battle.test.jsx` 10개(플래그 꺼짐=옛 화면, 카드→칸 저장, 지원 ②, 비우기, 휘두르기/지켜보기 1구, CSS 범위), 전체 612/613(실패 1 = 얕은 clone의 V12 baseline SHA, 코드 무관), build, zone report. 실제 브라우저 390×844 · 844×390 · 1440×900에서 2장 스택 → 투구 → 다음 공 → 새 화면 복귀, 오류 0. 플래그 꺼진 옛 흐름 스모크 통과.
- 캡처: `bp1-{390x844,844x390,1440x900}.png`.

## BP-2 기록 · 2026-09-25 — 투구 결과를 장면 안에서

- 플래그가 켜져 있으면 투구 연출·결과(`pitch`/`between`)·준비 카드 연출·스택 해결까지 볼파크 화면이 그린다. 옛 전투 화면으로 넘어가지 않는다. 마지막 공으로 투수가 내려가면 연출 뒤 보상 화면.
- 투수·타자는 옛 화면과 같은 애니메이션 컴포넌트(`PitcherAtlasSprite`, `Sprite`)를 그대로 받아, 와인드업·스윙 모션이 장면 안에서 돈다.
- 공: 투수 글러브에서 실제 공이 온 칸(존 밖이면 존 옆)으로 날아가 **임팩트 순간**(`timeline.impactAt`)에 떨어진다. 착지 전엔 HP 숫자·눈금이 그대로, 착지 후 눈금이 붉게 깎이고 `-N`이 뜬다.
- 판정: `presentationFor`의 한 단어 제목("한 칸 차이", "넘겼다")을 크게, 그 위에 야구 판정("헛스윙"), 아래 줄에 이유 한 문장. 좋은 결과만 강조색.
- 판정 자리: 세로 = 투수 왼쪽 하늘, PC = 존 위, 짧은 가로 = 마운드 앞 잔디. HP 태그와 존을 가리지 않는다.
- 버튼: 결과가 나오면 동사 두 개 대신 하나 — "다음 공 / 같은 타자" 또는 "다음 타자 / N번 이름". 연출 중엔 잠김. 손패는 흐리게.
- 검증: 테스트 12개(+2: 같은 화면에서 판정·실제 공·다음 버튼, 옛 플래그 이름 이전), 전체 614/615(실패 1 = 얕은 clone의 V12 baseline SHA), build, zone report. 브라우저 390×844 · 844×390 · 1440×900에서 한 판 끝까지(9구, 오류 0), 투수 HP 1에서 최종타 → 보상 화면. 플래그 꺼진 옛 흐름 스모크 통과.
- 캡처: `bp2-{390x844,844x390,1440x900}-result.png`, `bp2-390x844-impact.png`.
- 남음: 볼카운트 불빛은 착지 전에 이미 바뀐다(엔진이 결과를 먼저 저장). 옛 결과 화면의 상세(이유 사슬 `ResultChain`, 첫 두 타석 해설)는 아직 없다.
