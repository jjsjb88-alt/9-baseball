## 왜 바꾸나

- 픽셀 조정(12px 하한, 겹침 수정)으로는 "별로"가 해결되지 않았다. 문제는 디자인 방향이었다.
- 전투 화면에 박스 9개와 설명문 12줄이 경기장 그림을 덮는다. 강조색이 없고, 그림체(SD 캐릭터 · 칠한 경기장 · 웹 패널)가 서로 다른 게임처럼 보인다.
- 문구가 규칙 설명서처럼 길고 현학적이다.
- 기준: 아르티스 임팩트처럼 장면 하나가 화면이 되는 도트 게임.

## 다섯 가지 규칙 (모든 화면)

1. **장면이 먼저.** 위아래 검은 띠 안에 경기장 한 장면. 정보 패널은 장면 위에 올리지 않고 띠로 내린다.
2. **강조색은 하나.** 조명 노랑 `#ffc861`만. 노리는 칸, 휘두르기 버튼, 볼카운트 불빛, 갈 수 있는 지도 칸. 나머지는 남색 `#141a33` · 먹색 `#07080d` · 뼈색 `#ece4cf` · 청회색 `#7b84a6`.
3. **UI는 그림 속에.** 9존은 중계 화면처럼 타석 앞에 뜬 스트라이크 존. 투수 HP는 머리 위 눈금 12칸. 볼카운트는 구석의 작은 불빛.
4. **행동은 동사 두 개.** "휘두른다" / "지켜본다". 효율·커버 계산은 버튼 아래 한 줄. 원문 규칙은 카드 상세 시트.
5. **설명하지 말고 말하기.** 짧은 해설자 톤. 불확실함은 "확정 예고 아님" 같은 단서 대신 속삭이는 글씨체(기울임)로.

글꼴: 제목 Black Han Sans, 본문 Gowun Dodum, 숫자·라벨 Silkscreen.

## 지도

투수는 검은 실루엣, 갈 수 있는 곳만 노랗게 빛난다. 시설은 7×7 도트 아이콘. 누르면 아래(휴대폰) / 오른쪽(PC)에 컬러 초상화 · 한 줄 성격 · HP 눈금 · 보상 한 줄. 2·3막은 한 줄 예고.

## 미정

- 말투: 해설자 톤(시안) vs 코치 반말 톤.
- 캐릭터: SD 캐릭터가 경기장보다 밝고 깨끗해 떠 보인다. 경기장 밀도로 다시 그릴지.

## 구현 계획

기존 전투 화면은 CSS 30여 개 층이 `.duel-combat`을 덮어쓰고, 카드 배치는 DOM 스크립트(`stack-direct-tap.js`)가 숨은 React UI를 대신 누르는 구조다. 이 위에 또 덮어쓰지 않는다. **새 컴포넌트를 옆에 세우고 플래그로 켠다.**

## NG-1 기록 · 2026-09-25

- `src/duel/NightBattle.jsx`, `nightgame.css`(모두 `.ng-*`), `nightgame-copy.js`. App은 `?ng=1`(기억됨, `?ng=0`으로 끔)일 때 `phase==='battle'`·연출 없음에서만 새 화면을 그린다. 투구 연출·결과는 옛 화면.
- 입력: 카드 → 칸 = 메인(엔진 `setAimZone`), 메인이 있을 때 다른 카드 → 칸 = 지원(②③④, `swingStack`), 메인 다시 누르면 비움. 준비 카드는 원형 토큰, 버튼이 "준비한다"로 바뀜.
- 9존 칸 밝기 = 투수가 던질 몫(`publicProbabilities`), 던지지 않는 코스는 빗금.
- 글꼴은 `index.html`의 Google Fonts 링크(전역 로드, 쓰는 곳은 `.ng-battle`만). 이 컨테이너는 외부 글꼴이 막혀 캡처에는 대체 글꼴이 보인다.
