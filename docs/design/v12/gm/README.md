## 방향

홈플레이트 뒤 카메라에서 본 한 판의 대결 장면이다.

**v2 (LOOP 1): 한 픽셀 격자.** 화면 전체를 195×422 아트 캔버스에 칠하고 정확히 2배로 보여준다. DUGOUT 원본(경기장·타자·투수)은 로드 시 이 격자로 다시 샘플링한다(칸별 다수결, 공용 팔레트, 1px 잉크 재구성, 노을 역광 림라이트). 배우·경기장·9ZONE·카드·버튼이 같은 픽셀 크기와 같은 빛을 공유한다. 넓은 빛·그늘은 디더 대신 단계 알파로 칠한다. 한글은 기기 해상도 텍스트 층에 잉크 외곽선으로 올린다. 도구는 `pixel-kit.js`, 구성은 `scene.js`에 있다. v1(CSS 콜라주)은 `d1-golden-master-v1.html`과 `../shots/d1-gm-v1-390x844.png`에 비교용으로 남겼다.

1. **공간**: DUGOUT `assets/duel/stadium.png` 한 장이 전경부터 하늘까지 공간을 맡는다. CSS 그라디언트 배경판을 쓰지 않는다.
2. **대치**: 멀리 마운드에 와인드업하는 투수, 카메라 가까이에 큰 타자가 선다. 크기 차이가 거리감을 만들고, 투수의 공 쥔 손과 타자의 시선이 하나의 대각선에 놓인다.
3. **HUD**: 상대 이름·유형·HP·카운트는 외야 전광판 위치에 둔다. 장면과 분리된 상단 판을 쓰지 않는다.
4. **9ZONE**: 홈플레이트 위에 서 있는 빛나는 스트라이크존 프레임이다. 모서리 브래킷, 중계 화면식 3등분 눈금, `9 ZONE` 탭, 플레이트로 떨어지는 빛, 하단의 효율·CONNECT 띠를 하나의 장치로 묶었다.
5. **카드**: 홈플레이트 오각형 실루엣에 야구공 실밥 모서리를 달았다. 스택에 들어간 카드는 들려 있고 보드와 같은 순번 토큰(① 금색 메인, ②③ 청록 지원)을 단다.

## 읽는 순서

전광판(상대·HP·카운트) → 투수 의도 → 9ZONE(음영·커버·순번·연결) → 효율·CONNECT → 손패 순서 → 스윙 확정.

## 계약 준수

모든 수치와 칸은 P0 fixture를 실제 엔진에 넣어 계산한 값이다. 손으로 적은 값이 없다.

- **C1 커버**: `previewV10Stack`의 `primaryCoverage`와 `supportCoverages`를 쓴다. 메인 밀어치기는 존 5 기준으로 [2,5,8], 지원 정타 노림은 [4]와 [2]이다.
- **C2 연결**: `stackPlan.links`를 쓴다. 5→4, 4→2 모두 8방향 인접이라 CONNECT 2/2다. 카드끼리 닿는 모양을 연결로 쓰지 않는다.
- **C3 효율**: `damageRate` 0.79를 "피해 효율 79%"로 표시한다. HP 바는 72/72 그대로 두고, 깎일 구간을 그리지 않는다.
- **C4 읽기**: `readLevel`은 0이다. 음영은 `shadeFor`의 3단계만 쓰고, 0%라고 단정하는 표시는 없다.
- **C5 누설**: 공 궤적은 존에 닿기 전에 사라진다. `pending.zone`은 시안에 들어가지 않는다.
- **C6**: 엔진 공식을 다시 구현하지 않고 함수를 호출해 읽는다.
