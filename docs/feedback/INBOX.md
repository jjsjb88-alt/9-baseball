### 10. 전투 화면 UI/UX 마스터 규격 (6·7·9보다 우선)

2026-09-22 플레이테스트: *"1스테이지에서 쥬금 · 너무 복잡 어려움"*,
*"이펙트 때문인지 게임느낌은 훨 나는데, 야구 초보나 겜초보에겐 좀더 직관적이어야 할듯"*.

사용자 방향: **텍스트 최대한 줄이고 그래픽·효과로 치환. 게임 방식은 그대로.**

규격: [`docs/V12-UI-MASTER-SPEC.md`](../V12-UI-MASTER-SPEC.md). 검수·수정은 아스트라.

실제 빌드 계측(규격 §1.0): 보이는 텍스트 **211개**, 그중 **11px 미만 186개(88%)**, 최소 5.5px,
문서 높이가 뷰포트의 **1.95배**, 투수 HP는 9존 조작 중 **화면 밖**. 시안은 `docs/design/v12/`.

정적 감사 결과 텍스트 개수는 다섯 번째 문제였다. `src/duel/*.css` 21파일 5258줄에
`!important` 2266개(전체 줄의 19.5%), 색 리터럴 2106종 대 토큰 11개,
**11px 미만 글자 선언 433곳(최소 5.5px)**, z-index 51종, 이징 53종, 브레이크포인트 24종.
위계가 없고 글자가 읽히지 않는 것이 "복잡하다"의 실제 원인이다.

순서: **P0 토큰·레이어 기반(화면 변화 0) → P1 타이포 → P2 예상 피해 고스트 통합 →
P3 시각 언어 → P4 정리 → P5 무언 데모.** P0를 건너뛰면 이후가 또 `!important`가 된다.

주의: 표시 텍스트를 지우기 **전에** 테스트 단언을 `data-*`/`aria-label`로 먼저 옮긴다
(9개 테스트 파일 33곳이 화면 문자열에 의존).

밸런스·시스템 개수·판정 연출 강도는 이 항목의 대상이 아니다.

### 6. 접근성을 한 번 훑는다

- 9존 그리드를 키보드 방향키로 이동할 수 있는가
- 보상 화면의 4단계가 스크린리더에서 순서대로 읽히는가
- 명암만으로 정보를 전달하는 구간(등급 0)에 색 이외의 단서가 있는가 — **1번과 직접 충돌하므로
  1번을 먼저 끝낸 뒤에 한다**
- `prefers-reduced-motion`을 실제로 존중하는가

발견한 것 중 고칠 수 있는 것만 고치고, 나머지는 STATUS에 남긴다.

### 7. 강화 7종·유물 3종의 상대 가치를 잰다

`scripts/`에 덱 편집과 유물을 실제로 쓰는 리포트를 추가한다. 같은 시드에서 아무것도 없을 때 대비
각 강화/유물 1종만 적용했을 때의 완주율 차이를 낸다. `scout+`(열 정보)가 가장 강할 것으로
예상되며 그게 사실인지 숫자로 확인한다. 자동 정책에 제거·강화·유물 경로가 없으므로
정책 쪽에도 최소한의 경로가 필요하다.

### 9. 라이선스를 정한다

공개 배포 중인 저장소에 이용 조건이 없다. 무엇으로 할지는 사용자 결정이 필요하므로
**직접 고르지 말고** `docs/STATUS.md`에 "사용자 확인 필요"로 올려둔다. 파일을 만들지 않는다.
