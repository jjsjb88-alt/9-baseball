## 미처리 지시

### 4. 죽은 코드 마지막 세대를 정리한다

현행 진입점은 `src/duel` 하나인데 저장소에는 폐기된 세대가 남아 매 배포마다 검사가 돈다.

- `src/game/` (NIGHT RUN / CORE TEST)
- 그에 딸린 `tests/run-*`, `tests/core-test-*`, `tests/showdown-*`
- `scripts/core-test-report.js`

**반드시 지우기 전에** `src/main.jsx`부터 import 그래프를 따라가 `src/duel`이 이들 중 무엇도
참조하지 않음을 확인한다. 하나라도 참조하면 그 항목은 건너뛰고 이유를 STATUS에 적는다.
git 이력이 보존하므로 복구 가능하다. `package.json`의 관련 스크립트도 함께 정리한다.
한 바퀴에 전부 하지 말고 한 세대씩 해도 된다.

### 5. `HANDOFF.md`를 읽을 수 있는 크기로 되돌린다

80KB · 26개 절이고 대부분 역사다. 새 세션이 현행을 판별하는 비용이 계속 커진다.
최신 2개 절만 본문에 남기고 나머지는 `docs/history/HANDOFF-archive.md`로 옮긴다.
링크를 남겨 이력을 잃지 않게 한다. `README.md`도 같은 문제가 있으니 같은 방식으로 정리한다.

### 6. 접근성을 한 번 훑는다

- 9존 그리드를 키보드 방향키로 이동할 수 있는가
- 보상 화면의 4단계가 스크린리더에서 순서대로 읽히는가
- 명암만으로 정보를 전달하는 구간(등급 0)에 색 이외의 단서가 있는가 — **1번과 직접 충돌하므로
  1번을 먼저 끝낸 뒤에 한다**
- `prefers-reduced-motion`을 실제로 존중하는가

발견한 것 중 고칠 수 있는 것만 고치고, 나머지는 STATUS에 남긴다.

### 7. 강화 7종·유물 3종의 상대 가치를 잰다

`scripts/`에 덱 편집과 유물을 실제로 쓰는 리포트를 추가한다. 같은 시드에서 아무것도 없을 때 대비
각 강화/유물 1종만 적용했을 때의 완주율 차이를 낸다. `scout+`(열 정보)가 가장 강할 것으로
예상되며 그게 사실인지 숫자로 확인한다. 자동 정책에 제거·강화·유물 경로가 없으므로
정책 쪽에도 최소한의 경로가 필요하다.

### 8. 모바일 390px에서 보상 화면을 검사한다

덱 구성 칩(`.profile-chip`), 변화량 목록(`.delta-list`), 유물 카드(`.relic-card`)가
390px에서 겹치거나 잘리지 않는지 실제 화면으로 확인하고 필요한 것만 고친다.
데스크톱 레이아웃을 망가뜨리지 않는다.

### 9. 라이선스를 정한다

공개 배포 중인 저장소에 이용 조건이 없다. 무엇으로 할지는 사용자 결정이 필요하므로
**직접 고르지 말고** `docs/STATUS.md`에 "사용자 확인 필요"로 올려둔다. 파일을 만들지 않는다.
