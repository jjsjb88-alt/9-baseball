## 미처리 지시

- **정책 봇이 읽기 등급을 존중하게 만들고 등급별 완주율을 측정한다.**
  지금 `src/duel/policy.js`는 `publicProbabilities`를 그대로 읽어서 `readLevel`과 무관하게
  정확한 확률을 본다. 그래서 `pnpm report:growth`의 188/270은 "정보를 완전히 갖춘 플레이어"의
  상한이지 실제 체감이 아니다. 등급 0(명암)·1(구간)·2(정확)에서 각각 어떤 결정을 내리는지
  분리하고, 리포트에 등급별 행을 추가한다. 등급 0 봇은 `shadeFor` 수준의 정보만 써야 한다.

- **레퍼토리가 넓어지는 순간을 화면에서 읽히게 한다.**
  지금은 `baseIntent`의 `detail` 문장과 `read-state`의 "레퍼토리 N/9"에만 있다.
  타석이 넘어가며 존이 하나 늘어나는 순간이 플레이어에게 사건으로 보여야 한다.
  이미 있는 `s.last.events` / 로그 경로를 쓰고, 새 애니메이션 시스템을 만들지 않는다.

- **강화 7종의 상대 가치를 재는 리포트를 만든다.**
  `scripts/`에 덱 편집을 실제로 쓰는 리포트를 추가한다. 같은 시드에서 강화 없음 대비
  각 강화 1종만 적용했을 때의 완주율 차이를 낸다. `scout+`(열 정보)가 가장 강할 것으로
  예상되며, 그게 사실인지 숫자로 확인한다.

- **모바일 390px에서 보상 화면을 검사한다.**
  덱 구성 칩(`.profile-chip`), 변화량 목록(`.delta-list`), 유물 카드(`.relic-card`)가
  390px에서 겹치거나 잘리지 않는지 실제 화면으로 확인하고 필요한 것만 고친다.
  데스크톱 레이아웃을 망가뜨리지 않는다.
