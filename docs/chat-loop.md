# 채팅에서 개발·집필 분업 루프

이 저장소의 루프는 서브에이전트 도구가 제공되는 ChatGPT Work/Codex 채팅에서도 진행할 수 있다. 터미널 런처를 중첩 실행할 필요 없이 현재 채팅의 네이티브 에이전트를 사용한다. 채팅에 GitHub 접근 권한과 필요한 작업 도구가 있어야 한다.

## 시작

게임 전체의 반복 개발은 [게임 자율개발 모드](../loop/GAME-AUTODEV.md)와 [별도 시작 프롬프트](../loop/game-autodev-prompt.md)를 사용한다. 사용자가 이 모드를 요청했을 때는 그 문서의 범위·예산·회차 계약을 적용한다. 아래는 기존 한 항목 실행 경로이며 자동 반복으로 바뀌지 않는다.

이 저장소가 연결된 채팅에서 다음과 같이 요청한다.

> 야구 분업 루프 시작. jjsjb88-alt/9-baseball의 AGENTS.md와 docs/chat-loop.md를 읽고, [이번 작업] 한 항목을 진행해.

새 채팅에서는 저장소 이름을 함께 적는다. 작업이 생략되면 저장소의 우선순위·미완료 항목을 확인한다. 근거가 없는 목표를 만들지 않는다. 구현에 필요한 선택이 사용자 결정권에 속할 때만 확인한다. 작업 준비·분업·검증은 이 지침으로 진행하며 원격 쓰기·PR·병합·배포 범위는 현재 사용자 지시와 기존 저장소 규칙으로 판단한다. 이번 작업을 넘어선 병합 권한으로 확대하지 않는다.

## 세션 진입

1. 최신 사용자 지시와 대상 저장소·브랜치를 확인한다. 지정 브랜치가 없으면 최신 main을 읽어 작업 기준을 잡고 변경은 작업 브랜치에 준비한다. 기존 작업을 덮어쓰지 않는다.
2. AGENTS.md 전체 → 이 문서 → `HANDOFF.md` 최신 관련 절 → `docs/ANTIGRAVITY-LOOP.md` → `docs/antigravity/QUEUE.md` 순으로 읽는다. 전체 자율개발 모드는 전용 큐도 읽는다. 원격 대상과 연결을 확인하고 이미 확인된 인증·승인 범위를 재사용한다. 회차마다 계정·승인 ID를 다시 묻지 않는다.
3. 현재 도구에 네이티브 에이전트·파일 편집·테스트·GitHub 쓰기가 있는지 확인한다. GitHub 파일을 읽었다는 사실만으로 프로젝트 .codex 설정이 로드됐다고 보고하지 않는다.
4. 범위·현재 근거·검증·중단 조건을 먼저 정하고 필요한 역할만 호출한다. 파일 존재 확인 한 번을 따로 위임하지 않는다.

## 역할과 모델

| 역할 | 채팅에서 요청하는 설정 | 작업 범위 |
| --- | --- | --- |
| 메인 | 현재 채팅에서 사용자가 선택한 모델·노력 수준 | 계획·통합·최종 판단 |
| explorer | gpt-6-luna / high | 파일·계약 탐색, 편집 금지 |
| worker | gpt-6-luna / high | 지정 파일 편집·관련 테스트 |
| researcher | gpt-6-luna / high | 필요한 공식 문서·설정 근거, 편집 금지 |
| reviewer | gpt-6.1-sol / high | 독립 검토, 편집 금지 |

현재 호출 API가 모델·노력 수준을 지원하면 역할별로 명시한다. 모델을 지정할 때는 허용되는 컨텍스트 전달 방식과 함께 목표·제약·허용 파일·필수 자료를 전달한다. 최대 동시 서브에이전트는 3개, 편집하는 worker는 하나다. 결과·diff·실제 검증을 메인이 확인하고 통합한다.

메인 모델은 채팅의 모델 선택 UI에서 정한다. 저장소 문서나 .codex/config.toml이 Work의 메인 모델을 강제로 바꾸지 않는다. 역할별 모델을 선택할 수 없거나 접근 권한이 없으면 해당 모델 분업은 BLOCKED로 보고하고, 지원되는 대안은 사용자 지시 범위 안에서만 사용한다. 다른 모델을 썼는데 지정 모델로 수행했다고 보고하지 않는다. 에이전트 도구가 없으면 실행한 척하지 않는다.

## 세 번의 검토

- 큰 계획 전: reviewer에 목표·현재 근거·제약·제안 접근법을 보내 범위와 위험을 확인한다.
- 동일 오류 두 번째: 오류와 이미 시도한 방법을 보내 잘못된 원인 탐색·재시도 방향을 점검한다.
- 긴 작업 완료 전: diff·실제 테스트·미검증·사용자 요구 충족 여부를 보내 누락을 확인한다.

별도 reviewer를 호출하는 방식이며 Fable 또는 상시 advisor가 필요하지 않다. reviewer가 모든 세션·도구 호출·비공개 대화를 자동으로 읽는다고 가정하지 않는다. 기존 검수 범위·횟수를 늘리지 않고 동일 검수자에게 변경분을 이어 전달한다.

## 채팅 화면과 보고

네이티브 서브에이전트 활동·결과는 클라이언트가 제공하는 화면에서 확인한다. 메인은 작업 시작·검토·구현·검증·완료/차단 시점에 짧은 상태를 알린다. 사용자가 진행 상황을 물으면 실제 결과로 답한다.

| 항목 | 보고 내용 |
| --- | --- |
| 현재 단계 | 실제 수행 중인 작업과 대상 |
| 역할 상태 | 호출한 역할의 대기·실행·완료·차단과 확인된 모델 |
| 검토 | 세 시점의 실제 조언과 반영 결과 |
| 검증 | 실행한 검사·결과·미실행 항목 |
| 다음 한 단계 | 완료 조건 또는 남은 병목 |

비용·토큰·테스트 통과 수는 도구가 제공한 근거가 있을 때만 표시한다. 저장소의 localhost HTML 대시보드는 이 채팅 UI에 자동 삽입되지 않는다. 별도 화면은 [컴퓨터 실행 안내](codex-loop.md)를 따른다. 채팅에서 scripts/codex-loop.mjs를 다시 실행해 같은 목표를 두 세션으로 처리하지 않는다. 채팅 상태를 로컬 대시보드 로그로 자동 동기화한다고 주장하지 않는다.

## 프로젝트별 품질·중단 조건

기존 한 항목 모드에서는 사용자 지정 항목 또는 큐의 미완료 한 항목만 진행한다. 게임 전체 자율개발은 별도 계약의 예산 안에서 하나씩 반복한다. 구현 전 9축 영향도 분석을 수행하고 X1~X12·화면 회귀·테스트·smoke·production build 기준을 유지한다.

기존 한 항목 모드는 한 바퀴 후 변경분·독립 검토·검증·미검증·다음 한 단계를 보고하고 멈춘다. 전체 자율개발 모드는 체크포인트를 남기고 다음 독립 항목을 계속한다. 사용자 요청 없이 예약 작업이나 상시 실행을 만들지 않는다. 병합·배포가 실제로 완료된 경우에만 완료로 기록한다.
