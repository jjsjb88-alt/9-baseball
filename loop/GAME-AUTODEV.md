# 9ZONE HOMEBOUND 자율개발 루프

목표는 플레이어가 **투수를 읽고 → 카드와 존을 선택하고 → 결과를 이해하고 → 덱을 바꾸어 다시 도전하는 경험**을 상업 출시 수준으로 다듬는 것이다. 기능 수·커밋 수·에이전트 점수는 목표가 아니다. 현재 가장 크게 이 경험을 막는 병목 하나를 실제 플레이에서 찾아 제거한다.

이 문서는 게임 전체의 자율개발 모드다. [시작 프롬프트](game-autodev-prompt.md)를 현재 에이전트 세션에 전달하면 적용한다. 기존 `loop/PROMPT.md`, Codex/Claude 한 회 런처, Antigravity 시각 루프와 예약 작업은 자동으로 전환되지 않는다. 이 파일을 추가하는 것만으로 실행되지 않는다.

## 1. 진입과 실행 범위

“자율개발 준비해”는 현재 상태·도구·작업 후보·실행계획을 준비하는 요청이다. “게임 자율개발 시작해” 또는 시작 프롬프트를 실행하라는 요청은 아래 기본 범위의 개발을 시작하는 지시다. 이미 승인된 범위가 있으면 재사용한다. 기존 문서의 과거 승인 기록만으로 이번 범위를 확대하지 않는다.

| 항목 | 기본 범위 |
| --- | --- |
| 대상 | `jjsjb88-alt/9-baseball`, 현재 실제 `origin/main` 기준 |
| 작업 | 재현된 진행 버그, 현행 규칙에 맞춘 표시·입력·가독성·안내·화면 내 배치 개선, 기존 승인 자산 연결 |
| 산출물 | 작업 브랜치의 변경·테스트·검수 근거·로컬 커밋·체크포인트 |
| 예산 | 최대 6회차 또는 시작 후 120분 중 먼저 도달하는 시점. 실패·보류 회차도 포함 |
| 원격 | 기존 명시 권한을 재사용. 없으면 로컬까지만 진행하고 원격 대기로 기록 |
| 제외 | 세계관 확정, 핵심 규칙·밸런스·런 구조 변경, 저장 스키마 변경, 패키지 추가, 전역 CSS 개편, 새 유료 서비스·예약 실행 |

총괄은 `loop/autodev/runs/<실행-id>.md`에 기준 SHA, 실제 지시·승인 근거, 허용 범주, 원격 대상·브랜치·PR·공개 권한, 회차·기한(KST), 도구·역할을 적고 시작한다. 실행 ID는 에이전트가 만든다. 사용자가 승인 ID·계정을 매회 입력하게 하지 않는다. 최신 지시가 더 좁으면 그 범위를 따른다.

범위 안의 작은 구현·검수·커밋과 이미 허용된 브랜치 push·PR은 회차마다 다시 묻지 않는다. 인증은 정상 CLI/연결로 재사용하며 비밀키를 채팅에 요구하지 않는다. 계정·대상 변경이나 인증 실패 때만 실제 오류를 확인한다. 플랫폼 자체의 권한 창은 이 문서로 없앨 수 없다.

`main` push는 Vercel·Pages 공개 배포를 일으킨다. 기본 공개 권한은 없다. 공개 반영을 별도로 허용받은 총괄만 검증된 변경을 반영한다. Antigravity 실행자는 [기존 X1~X12](../docs/ANTIGRAVITY-LOOP.md)를 유지하고 PR·프리뷰까지만 진행한다. 스스로 PR 승인·auto-merge·force-push하지 않는다.

## 2. 먼저 확인할 근거

1. 최신 사용자 지시 → `AGENTS.md` 전체 → 이 문서.
2. `git status`, 현재 브랜치·HEAD·origin, 최신 main과 차이, 다른 실행·열린 PR·변경 파일.
3. [게임 큐](autodev/QUEUE.md), 최근 실행 체크포인트, [실제 피드백](../docs/feedback/INBOX.md).
4. `HANDOFF.md`와 `docs/STATUS.md`의 관련 최신 기록. 날짜가 다른 “현재” 절이 충돌하면 코드·SHA·실행 결과로 판별한다.
5. 변경 영역의 엔진·화면·테스트 전체와 규칙 계약(`docs/DECK.md`, `docs/DUEL.md`, `docs/RUN-STRUCTURE.md` 등).
6. 시각 변경은 [목표 목업](../docs/design/v14/TARGET-MOCKUP.md), [아트 기준](../docs/art/QUALITY-BAR.md), 승인 자산·현재 연결 상태.

체크된 옛 큐·높은 점수·옛 테스트 수·이미지 존재를 현재 완료 근거로 쓰지 않는다. 세계관 초안·검수 권고는 작가 확정과 다르다. 여성 투수·등장인물 수 등의 설정을 자율적으로 판타지 설정으로 바꾸지 않는다.

## 3. 에이전트 분담

총괄 아래 최대 3개 서브에이전트, 같은 체크아웃의 편집자는 한 명이다. 총괄이 문서·큐를 갱신할 때도 구현자의 편집을 멈추고 순서대로 쓴다. 독립적인 읽기만 병렬화한다. 이 루프를 위해 새 worktree를 자동으로 만들지 않는다. 기존 다른 세션이 편집 중이면 같은 작업을 시작하지 않는다.

| 역할 | 책임 | 편집 권한 |
| --- | --- | --- |
| 총괄 | 근거 수집, 우선순위·영향도 결정, 위임, 통합·허용 원격 반영, 체크포인트 | 구현자와 겹치지 않는 시간에만 |
| 구현 | 선택한 문제 하나의 좁은 수정과 관련 회귀 검사 | 지정 파일만, 원격 쓰기 금지 |
| 플레이·UX 검수 | 새 플레이어의 첫 화면부터 입력·판정·보상·시설·이어하기 검수, 실제 PNG·영상 비교 | 제품·테스트 편집 금지 |
| 독립 코드 검수 | 원인·diff·엔진 계약·저장 호환·정보 경계·회귀·검증 누락 점검 | 제품·테스트 편집 금지 |

Codex 채팅에서는 [채팅 역할 모델](../docs/chat-loop.md)을 적용한다. 구현은 worker, 플레이·UX는 explorer, 독립 코드는 reviewer에 해당한다. Claude에서는 worker·ag-qa·ag-reviewer와 advisor 지침을 적용한다. OpenCode에서는 사용 가능한 위임 도구·모델을 확인하고 같은 책임을 전달한다. 특정 무료 모델이 한국어·재미·코딩에서 최고라고 가정하지 않는다.

같은 모델의 **별도 호출**도 독립 검수가 될 수 있다. 원저자의 자기검수만으로 통과시키지 않는다. 서브에이전트나 지정 모델을 사용할 수 없으면 실제 상태를 보고하고 독립 검수 전 통합·원격 게시를 보류한다. 읽기·재현·로컬 후보 준비는 계속할 수 있다. 혼자 역할 이름만 바꾼 것을 독립 검수로 기록하지 않는다.

큰 계획 전, 같은 오류 두 번째, 긴 작업 완료 전에는 기존 reviewer/advisor 체크포인트를 유지한다. 같은 검수자에게 수정분과 해결 근거를 이어 전달하고 새 검수자로 바꿔 오류를 지우지 않는다.

위임에는 이슈 ID·기준 SHA·목표·허용 파일·금지 범위·재현 입력·통과 조건을 포함한다. 결과에는 실제 모델·실행한 명령·종료 상태·파일/줄 근거·미실행 검증·남은 결함을 받는다. 구현자가 PASS 조건을 바꾸지 않는다.

## 4. 병목을 고르는 순서

| 우선순위 | 플레이어 문제 | 근거 예시 |
| --- | --- | --- |
| P0 | 진행 불가, 저장 유실·복원 오류, 입력 후 다른 행동 실행, 판정·표시 불일치 | 재현 입력·상태·콘솔·실패 검사 |
| P1 | 첫 5분에 할 일·카드 효과·결과 원인을 이해하기 어려움, 폰에서 읽거나 누르기 어려움 | 실제 화면·입력, 사람이 막힌 지점 |
| P2 | 중반 선택이 같은 답으로 수렴, 덱 변화·상대 차이가 체감되지 않음, 반복 연출 피로 | 동일 시드 비교, 공개 정보만 쓰는 정책, 사람 플레이 |
| P3 | 화풍·모션·사운드·서사 연결·마감·출시 준비 부족 | 현재 화면/영상·승인 기준·실제 파일 연결 |

우선순위가 높아도 권한·선행 조건이 없으면 보류하고 다음 독립 항목을 고른다. 사람 자료가 없는 항목은 가설로 기록한다. 에이전트가 대신 플레이했다고 인간 재미·이탈률·구매 의향을 측정한 것으로 쓰지 않는다.

기존 큐와 미완료 PR을 이슈 ID·관련 파일·증상으로 대조한다. 이미 처리 중이면 중복 구현하지 않는다. PR 조회가 불가능하면 미확인으로 남기고 겹칠 가능성이 있는 구현은 보류한다. 새 항목은 실제 재현·구체 피드백·관찰 증거가 있을 때만 이 게임 큐에 추가한다. 기존 INBOX·Antigravity 큐를 자동으로 확장하지 않는다.

## 5. 한 회차

1. **정합성 확인**: 실행 범위·남은 예산·기한·다른 편집 세션·기준 SHA·PR 의존성을 확인한다. 직전 미반영 변경을 현재 main의 사실로 가정하지 않는다.
2. **Before 확보**: 현재 코드를 실행해 문제를 재현한다. 동일 시드·행동·덱·읽기 등급·뷰포트·기기 조건과 기대/실제 결과를 기록한다. 필요하면 baseline 전체 검사도 한 번 실행해 기존 실패를 분리한다.
3. **한 문제 선정**: “무엇을 바꾸면 플레이어의 어떤 판단/행동이 나아지는가”를 한 문장으로 적고, 수정 전 통과 조건을 정한다. 화면 장식 추가만으로 진척을 만들지 않는다.
4. **영향도 분석**: AGENTS의 9축과 PR 템플릿의 10개 체크를 채운다. 공용 함수·전역 CSS·저장·입력 경로는 관련 화면 전체를 분석한다. 너무 큰 변경은 독립 항목으로 쪼갠다.
5. **구현**: 재현 버그는 가능하면 실패 검사부터 확인하고 좁게 수정한다. 규칙 공식은 엔진 값을 재사용한다. 자산은 기존 검색→실제 연결 확인→필요성 판단 순서다. 승인 없는 설정·밸런스·스키마 변경은 제안 파일까지만 준비한다.
6. **기술 검증**: 관련 검사, 전체 테스트, 기존 smoke, production build·용량 검사와 변경 영향 화면의 실제 입력을 확인한다. 명령 종료 코드와 출력 내용을 함께 본다.
7. **독립 검수**: 코드 검수자는 실제 diff·계약·실패/미실행 결과를 읽는다. 시각 변경은 먼저 맥락을 분리한 새 판정 호출에 기준|A|B 이미지·8축만 전달해 블라인드 점수를 봉인한다. 후보 플레이·코드·diff·원저자 설명은 이 호출에 전달하지 않는다. 점수를 적은 뒤 reveal하고, 이후 플레이 검수자에게 버전별 상태를 전달해 같은 조건의 실제 흐름을 검수한다. 후보를 이미 본 에이전트에게 블라인드 판정을 맡기지 않는다.
8. **수정 또는 보류**: CHANGES/FAIL이면 같은 이슈를 고쳐 필요한 검증만 다시 한다. 같은 오류 두 번째에는 원인 상담을 받는다. 수정은 이슈별 누적 최대 3회이며 새 회차·세션·검수자에서 초기화하지 않는다.
9. **허용 반영**: 검증된 이슈 하나를 커밋한다. 원격 권한이 있으면 지정 브랜치·PR로만 게시하고 실제 PR/프리뷰 링크를 기록한다. 권한이나 도구가 없으면 로컬 검증 상태로 남긴다. 공개 권한·배포 확인 없이 공개 완료로 쓰지 않는다.
10. **체크포인트 후 다음 회차**: 이슈 상태·소유 실행·SHA·수정 횟수·실제 검증·가장 큰 남은 병목을 기록한다. 예산 안에서 다음 독립 항목을 계속한다.

로컬 연속 모드는 원격에 게시하지 않는 내부 브랜치에만 검증된 이슈별 커밋을 순서대로 남길 수 있다. 이는 새 모드의 로컬 기록 예외이며 다음 회차 기준은 그 실제 HEAD다. `main` 반영으로 표현하지 않는다. 원격 게시 시 이 브랜치를 통째로 다중 이슈 PR로 올리지 않고 최신 main 기준의 이슈별 독립 브랜치·PR로 분리한다. 분리된 변경을 다시 검증하고, 앞 변경 없이는 검증할 수 없는 항목은 병합 전까지 `HELD`로 남긴다. Antigravity의 한 항목=한 브랜치=한 PR 규칙은 그대로다. 미병합 PR에 의존하는 항목을 최신 main에서 다시 구현하지 않는다.

## 6. 검증 게이트

### 기술·흐름

저장소 루트에서 기본 코드 검증을 실행한다. 이미 설치된 고정 의존성을 쓰고 설치가 필요하면 `pnpm install --frozen-lockfile`을 따른다.

```bash
pnpm test
node scripts/zone-report.js 10
pnpm build
pnpm check:dist
```

영향에 따라 현행 V10/지도·덱·성장 리포트와 관련 회귀 검사를 추가한다. 옛 세대 정책의 report가 성공했다고 MAIN RUN을 검증한 것으로 쓰지 않는다. `scripts/v10-report.js`처럼 JSON 지표를 출력하는 리포트는 종료 코드 0만으로 판정하지 않고 유효 지도·보스 경로 등 실제 지표를 비교한다.

필수 흐름은 타이틀/메뉴 → 새 런 → 경로/스크롤 → 전투/9존 → 카드 선택·순서·스택 → 투구/HP/결과 이유 → 보상 → 시설 → 다음 경로 → 저장/리로드/이어하기다. 승리·패배·취소·연속 탭·입력 잠금·손상 저장·저장 실패 중 영향을 받는 경로도 확인한다.

UI는 공개 정보 등급·단서 경계를 보존한다. 정확 확률을 아는 정책과 제한 정보를 쓰는 정책을 구분한다. 승률·피해 변화는 동일 시드·정책·조건에서 비교하며 사람 난이도·재미로 바꾸어 쓰지 않는다.

### 브라우저·시각·동작

현행은 **세로 전용**이며 PC는 `PortraitFrame` iframe, 휴대폰 가로는 회전 안내다. 가로 UI를 새로 만드는 것을 개선으로 취급하지 않는다. 세로 390×844·412×743·375×667, 가로 844×390, PC 1440×900을 검사한다. PC는 실제 iframe 안으로 들어가 플레이하고, 휴대폰 가로는 터치 기기 조건에서 안내와 복귀·진행 보존을 확인한다. 세로→가로→세로의 **같은 진행 상태**를 검사한다.

```bash
pnpm dev --host 127.0.0.1 --port 5199 --strictPort
```

서버의 실제 응답과 게임 진입을 확인한 뒤 별도 터미널에서:

```bash
node scripts/qa-shots.mjs --url http://127.0.0.1:5199 --out work/autodev-current
```

이 스크립트의 현재 자동 범위는 **412×743·375×667의 저장 fixture 기반 지도·전투·보상**이다. 이것만 실행하고 모든 화면·회전·PC·전체 새 런을 검증했다고 쓰지 않는다. 브라우저 도구로 나머지를 실제 입력·PNG·타임라인으로 보완하고 결과를 회차 파일에 기록한다. `PLAYWRIGHT_MODULE`·`CHROMIUM_PATH`는 실제 설치 경로만 지정한다. QA 도구의 옛 노드 ID·Windows 경로·fixture가 현행 코드와 맞는지 확인하고, fixture가 깨지면 제품 결함과 구분한다. 도구 수정도 별도 영향도·검수를 거친다.

스틸 이미지로 모션·타격감·소리·진동을 판정하지 않는다. 투구·타격·홈런·파울·삼진의 시간 흐름, 연타 시 중복 처리, reduced-motion·음소거·WebGL fallback을 해당 조건에서 검증한다. 브라우저 측정은 기기·네트워크·소프트웨어 렌더링 조건을 함께 적고 실기기 성능으로 일반화하지 않는다.

시각 개선에는 기존 `QUALITY-BAR.md`의 기준·블라인드 판정·IMPROVED/BAR_MET 조건을 유지한다. 동일 상태·파일 이름으로 Before/After를 준비하고 `scripts/compare-shots.mjs`를 사용한다. 총괄이 시트를 만들고 새 판정 호출에는 기준|A|B와 8축만 전달한다. key·버전 라벨·후보임을 알려주는 메타데이터·코드·diff·기존 플레이 보고를 전달하지 않는다. 이 호출은 플레이·UX 역할의 슬롯을 재사용하고 동시 서브에이전트 3개를 넘기지 않는다. 점수가 봉인된 뒤에만 버전별 실제 플레이 검수를 수행한다. 모든 대상 시트·8축에 실제 점수가 있는지 확인한 뒤 reveal한다. 누락 시트·축이나 잘못 매칭된 목표 이미지를 통과로 세지 않는다. reveal이 변경한 `docs/art/QUALITY-LOG.md`도 검증 기록으로 검토한다. 아트 점수는 플레이 진행 회귀나 정보 유실을 상쇄하지 않는다.

### 사람 플레이·상업성

출시 목표와 사람 검증은 [플레이 검증 계획](autodev/PLAYTEST.md)에 따른다. 에이전트 기술 검수가 끝나도 `사람 검증 대기`를 별도로 남긴다. 실제 사람 자료가 없으면 기다리는 항목만 보류하고 독립적인 기술 개선을 계속한다. 사람에게 메시지를 보내거나 플레이 테스트를 모집하는 행동은 별도 지시 없이 수행하지 않는다.

## 7. 상태·중단·재개

| 이슈 상태 | 의미 |
| --- | --- |
| NEW | 과거 근거/가설, 현 HEAD 재현 전 |
| REPRODUCED / IN_PROGRESS | 현재 재현 완료 / 한 편집자가 작업 중 |
| VALIDATED_LOCAL | 필요한 로컬 검증·독립 검수 통과, 원격·공개 반영과 별개 |
| REVIEW_READY / PREVIEW_VERIFIED | 실제 PR 게시 / 실제 프리뷰에 동일 변경이 배포되고 확인됨 |
| RELEASE_VERIFIED | 허용된 공개 반영과 배포 후 해당 흐름 확인 완료 |
| HELD / NEEDS_HUMAN | 권한·도구·선행 변경·수정 한도 등 대기 / 실제 사람 증거가 필요 |
| NOT_REPRODUCED / REJECTED | 현 HEAD에서 재현 안 됨 / 변경이 목표를 개선하지 못해 채택하지 않음 |

AGENTS의 배포 후 확인까지 완료 정의는 유지한다. `VALIDATED_LOCAL`이나 PR 생성만으로 제품 구현·배포 완료를 선언하지 않는다. 회차 종료와 제품 완료도 구분한다.

한 항목의 도구 부재·미확정 설정·인간 검증·미병합 의존성은 `HELD`/`NEEDS_HUMAN`으로 남기고 다른 **독립적인 허용 작업**을 계속한다. 같은 실패 명령을 변화 없이 반복하지 않는다. 재현 못 한 문제는 수정하지 않는다. 검사가 기존부터 실패했어도 그 실패를 PASS로 바꾸거나 조건을 낮추지 않는다. 필수 검증 실패가 있는 후보는 통합·원격 게시하지 않는다. 실패를 고치는 독립 항목이나 읽기·진단은 계속할 수 있다.

전체 실행은 사용자 중단, 회차/기한 도달, 사용량 제한, 다른 편집 세션 충돌, 안전하게 진행할 항목 없음에서 종료한다. 인증 장애는 원격 작업만 보류하고 가능한 로컬 작업을 계속한다. 검사 실패·중단 후보도 보존하되 별도 파일/브랜치로 격리하고 다른 항목에 미검증 변경을 섞지 않는다. 사용자가 없는 동안 필요한 질문이 답변 대기를 독촉하게 만들지 않고 결정 목록을 남긴다. 승인 없는 범위 확장은 하지 않는다.

체크포인트에는 승인 범위·기준/현재 SHA·브랜치·작업자·이슈/상태·회차/수정 횟수·실제 검증/산출물 위치·원격/배포 상태·미반영 의존성·결정 필요·다음 한 행동을 남긴다. [템플릿](autodev/TEMPLATES.md)을 사용한다. 재개 때 누적 예산·수정 횟수를 유지한다. 보류 이슈는 새 증거·해결된 선행 조건·사용자 결정이 있어야 재처리한다. 새로운 예산은 사용자의 계속 진행 지시로 정한다.

활성 세션에서 실행하는 루프다. 창이나 세션이 끝난 뒤 계속 돌거나 120분에 강제 종료되는 데몬이 아니다. 총괄이 긴 명령에 타임아웃을 정하고 명령 전후 기한을 확인한다. 기존 CLI 런처는 여전히 한 회만 실행한다. 예약 작업·권한 우회·자동 로그인·추가 유료 호출을 설치하지 않는다.
