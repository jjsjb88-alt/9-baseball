# 게임 자율개발 시작 프롬프트

저장소가 연결된 Codex·OpenCode·Claude 세션에 아래를 붙여 넣는다. 기본 실행은 로컬 작업 브랜치, 최대 6회차/120분이다. 이미 허용된 GitHub 게시 범위는 재사용하며 공개 배포는 별도 범위다. 문서 생성 요청만으로 실행하지 않는다.

```text
jjsjb88-alt/9-baseball의 게임 자율개발을 시작해.

AGENTS.md 전체와 loop/GAME-AUTODEV.md, loop/autodev/QUEUE.md,
loop/autodev/PLAYTEST.md, loop/autodev/TEMPLATES.md를 먼저 읽어.
현재 사용자 지시, 실제 main/HEAD, 작업 트리, 다른 실행/열린 PR,
최신 HANDOFF·피드백·해당 영역의 코드와 계약을 확인해.
옛 큐·옛 점수·옛 “완료” 기록을 현재 재현으로 취급하지 마.

목표는 투수를 읽고 카드·존을 선택한 판단이 결과로 읽히며,
보상으로 덱을 바꾸고 다시 도전하고 싶은 게임을 만드는 것이다.
실제 플레이의 가장 큰 병목 하나씩 제거해.
마스터피스 판정이나 기능·커밋·테스트 수 증가를 목표로 삼지 마.

이번 기본 범위는 재현된 진행 버그, 현행 규칙에 맞춘 표시·입력·가독성·안내,
화면 내부 배치, 기존 승인 자산 연결과 관련 검증이다.
최대 6회차 또는 시작 후 120분 중 먼저 도달할 때 체크포인트로 끝내.
실패·보류 회차도 예산에 포함하고 재개한다고 수정 한도를 초기화하지 마.
최신 지시/기존 승인 범위가 다르면 실제 범위를 실행 파일에 적어.
이미 승인된 범주 안에서는 회차마다 승인·계정·승인 ID를 묻지 마.
기존 원격 권한이 없으면 로컬 커밋까지 진행해. 로그인 비밀키를 요구하지 마.
공개 반영 권한 없이 main push·merge·배포하지 마.
Antigravity 실행자는 언제나 기존 PR·프리뷰 한도를 유지해.

총괄 아래 구현, 플레이·UX 검수, 독립 코드 검수 에이전트를 분리해.
사용 가능한 네이티브 위임 도구와 실제 모델을 확인하고 기존 역할 모델 지침을 따라.
최대 3개 서브에이전트, 같은 체크아웃 편집자는 총괄을 포함해 한 명씩이다.
읽기는 병렬로 할 수 있지만 구현·큐 갱신·통합은 순서대로 해.
새 worktree·중첩 AI CLI·예약 실행은 만들지 마.
도구가 없으면 분업 성공이라고 하지 말고 독립 검수 전 게시를 보류해.
같은 모델의 별도 검수는 허용하되 원저자의 자기검수만으로 PASS하지 마.

먼저 실행 ID를 직접 만들고 loop/autodev/runs/<실행-id>.md에
기준 SHA·허용 범주·원격/공개 권한 근거·실제 도구/역할·예산·기한(KST)을 적어.
현재 게임을 실행하고 기준 상태를 측정한 뒤 첫 회차를 시작해.

회차마다 다음 순서를 따라:
1. 이슈 소유권·관련 PR·의존성·남은 예산 확인.
2. 현재 HEAD에서 재현하고 Before 시드·행동·상태·화면을 확보.
3. 플레이어가 겪는 문제 하나와 수정 전 통과 조건 선정.
4. 기존 9축 영향도·PR 템플릿 체크 완료.
5. 지정 파일의 좁은 구현과 의미 있는 회귀 검사.
6. 관련 검사 + 전체 pnpm test + 기존 smoke + pnpm build + pnpm check:dist.
7. 실제 입력으로 흐름·저장·회전·작은 폰·PC iframe 검수.
8. 독립 코드 검수와 플레이·UX 검수. 시각 변경은 먼저 새 판정 호출에 기준|A|B·8축만
   주어 블라인드 점수를 봉인하고 reveal한 뒤 실제 후보 플레이를 검수해.
   코드·diff·라벨 있는 Before/After·원저자 설명을 블라인드 호출에 주지 마.
9. FAIL/CHANGES는 같은 검수자에게 수정 근거를 이어 전달. 이슈별 누적 수정 최대 3회.
10. 검증된 변경만 허용된 범위에 반영하고 SHA·실제 결과·다음 병목 기록.
    내부 로컬 브랜치에 누적했다면 원격 게시 전 이슈별 독립 브랜치·PR로 분리하고 재검증해.
    의존 변경이 main에 없으면 해당 항목을 보류해. 다중 이슈 PR로 통째 게시하지 마.
11. 예산이 남으면 다음 독립 항목으로 계속해. 매회 다음 작업을 묻지 마.

현행 게임은 세로 전용이다. 휴대폰 가로는 회전 안내, PC는 PortraitFrame iframe을 검수해.
qa-shots.mjs의 실제 범위는 412x743·375x667의 fixture 기반 일부 화면이다.
그 성공만으로 새 런 전체·회전·390x844·844x390·1440x900을 검사했다고 하지 마.
브라우저 도구로 부족한 범위를 보완하고 스틸로 모션·소리·실기기 성능을 단정하지 마.
제한된 읽기 등급의 UI에 숨겨진 정확 확률을 유출하지 마.
검사 실패·미실행·독립 검수 부재를 높은 점수로 상쇄하지 마.

설정·핵심 규칙·밸런스·런 구조·저장 스키마·패키지·전역 CSS 개편은
이번 범위에서 자동 확정하지 말고 구체 제안으로 보류해.
하나가 막히면 증거와 필요한 결정을 남기고 다른 독립적인 허용 작업으로 넘어가.
재현 안 된 문제, 미반영 PR에 의존하는 문제, 같은 실패 명령은 반복하지 마.
사람 플레이가 필요하면 NEEDS_HUMAN으로 남겨. 재미·이탈·구매 의향 수치를 지어내지 마.
무작정 장식·에셋·아크·문서를 늘려 빈 큐를 채우지 마.

각 회차에 문제 / Before→After / 실제 검증 / 독립 판정 / 브랜치·원격 상태 /
미검증·결정 필요 / 다음 행동을 짧게 보고해.
로컬 검증·PR 대기·프리뷰 확인·공개 확인을 구분해.
종료 때 체크포인트와 사람이 확인할 후보·남은 가장 큰 병목을 남겨.
세션 종료 후 계속 실행된다고 주장하지 마.
```

게임 자율개발 재개해. loop/GAME-AUTODEV.md와 마지막 실행 체크포인트를 읽고,
